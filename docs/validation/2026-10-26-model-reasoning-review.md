# 中央模型推理能力边界审查

本文件记录模型选择器所需的中央能力契约，不代表生产中央服务已升级。没有修改数据库结构、费率算法、钱包账本、生产模型定义或服务器配置。

## 能力契约

模型不可变定义可选增加 `reasoning: {"efforts": ["low", "medium", "high"]}`。支持的值限定为 `minimal`、`low`、`medium`、`high`、`xhigh`、`max`，最多六项且不允许重复、额外字段或非字符串。显式空数组代表没有可选强度，字段缺失代表旧目录未声明能力。不能根据模型名称推断接口支持。

中央目录只公开已经验证的能力字段，`CentralClient._execution_view` 再进行有界白名单校验；供应商地址、密钥、验证资料等字段不会随能力元数据传给网页。能力列表复制保存，避免调用者之后更改输入对象。

任务认证从数据库中的不可变模型定义读取 `model_reasoning`，中央执行入口在 `admit` 前检查请求的显式 `reasoning.effort`。未知能力、不支持的档位和非法值在创建预留、调用供应商之前拒绝。请求不能通过自带能力声明扩展权限。旧客户端省略推理字段或仅提交 `summary` 时保持既有协议行为；不强加默认推理档位。推理参数参与既有规范化请求哈希，同一幂等键改档位会冲突并保留原操作。

原模型定义仍然不可修改。在实际供应商验证通过后，需要按既有发布流程发布新定义并安排版本切换，不能直接给旧模型补写一个未经验证的支持列表。未部署或未声明的生产目录在客户端保持能力未知。

## 本地请求链路独立只读复核

对 `easel/chat_models.py`、Web 请求接入、Pi 私有历史和前端选择状态作只读复核：模型 ID、目录 revision 和推理强度由后端再次校验；中央授权仍以服务器账号 scope 为准。Pi 历史只放宽模型字段，供应商地址和全部服务身份字段仍相等才可续聊；没有清空旧历史。前端使用会话 ID 作组件 key，拒绝卸载及旧序号的目录响应，运行前冻结选择快照，恢复连接仅查询原任务。

发现的目录加载前后身份竞态已交给本地实现者修复：不能因为公开字段相同，就将旧供应商或账号的目录放进新 authority；合法 token 刷新与供应商、账号、scope 改变必须区分。最终模型选择器总体验收应覆盖该修复的回归结果。

目录全局锁位于工作线程调用内，不占用事件循环；其同步网络读取会串行阻塞其他目录或选择工作线程，当前桌面单工作区范围可接受，不能据此声称多租户目录请求的性能已验收。另已提醒前端处理 120 秒目录 lease 过期后的刷新体验，不能自动重发已提交的模型请求。
