Mutations authenticate their required capability, require exact same-origin plus constant-time CSRF verification, accept only the expected JSON shape, and forward reason/idempotency proof to the catalog. No client-supplied actor is accepted. Catalog state changes include the expected update timestamp.

The host and API-origin guards, 64 KiB mutation body limit, duplicate-key rejection, sanitized error bodies, no-store data responses, no-referrer/nosniff headers and restrictive CSP are compatible with the frontend. Callback output never interpolates the raw callback URL; pending request identifiers are character/length constrained. Asset paths are filename bounded and resolved beneath the assets directory; SPA fallback is limited to known pages. The frontend uses external CSS, escaped text and same-origin requests, so it does not require weakening CSP.

Administrative commands require a separately configured owner DSN, compare its declared database target with Console settings, and verify actual schema ownership/current user before performing owner-only operations.
