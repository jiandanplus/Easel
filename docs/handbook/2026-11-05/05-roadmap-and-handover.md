# 05 · 路线图与交接清单

日期：2026-11-05。以下是后续建议顺序，不是已经恢复开发、批准生产维护或宣布正式上线。

## 1. 当前停在哪里

主功能已从 UI 改版推进到“本地 Pi + 中央统一账号／共享点数 + 私有运营 + 部分真实模型”的可运行系统。当前最耗时的收尾在完整媒体备份／隔离恢复与运行制品资格，不是只剩界面工作。

B3 正在 Task4 的原生重建链路：源捕获、角色计划和 owner 到 worker 的源码子门已有分段验证；最新 installed08 的实际 main／来源／安装入口源码有 287 项测试，另有 129 项互补测试。两套不是一次全项目测试，独立 review10 尚未收口，也没有据此完成新制品构建／安装资格或完整 SQL 恢复。

H3 身份交接、tablespace／GUC、有序 ACL、数据库重建与最终 LOGIN 仍有设计／开发／实际验证工作。双目标 ATTEST 成功仅证明限定 worker／执行条件，不证明数据库和应用恢复完成。

## 2. 后续阶段和验收门槛

| 顺序 | 工作包 | 最小交付标准 |
| --- | --- | --- |
| 1 | installed08 源码审查收尾 | 关闭独审发现，冻结新清单，按变更补限定回归；保留原测试终态 |
| 2 | B3 Task4 原生链路 | 独立来源、完整依赖闭包、固定入口、H3／角色／TS／GUC／数据库权限按正确顺序恢复 |
| 3 | B3 完整隔离恢复 | 新目标内数据库、身份、媒体、配置、序列、ACL、维护控制和低权应用验证；失败矩阵闭合 |
| 4 | B2/B3 生产备份接入 | 当前生产范围一致的真实捕获与 fresh restore；密钥恢复、容量、清理和 timer 具体发布验收 |
| 5 | AV 与后续媒体 | 完整 FFmpeg 来源／构建／运行权限；逐模型真实提交、轮询、下载、解码、计量与扣点 |
| 6 | macOS 正式候选 | 现有工作区接续、干净设备、登录、真实工具、点数、无障碍关联证据、签名公证／Gatekeeper |
| 7 | 商业订阅 | 用户明确套餐条款并安全配置商户后，真实收款、重复通知、退款、主动查单和对账 |
| 8 | 多产品与平台扩展 | 第二个真实产品接入统一身份／钱包且隔离正确；Windows／Linux及云端执行另验 |

支付配置是用户明确暂缓项；第二产品尚未指定。可以继续做不依赖这些输入的开发，但不能用合成产品或模拟支付声明商业模式已完整上线。

## 3. 当前不应承诺的能力

- 所有 New API 插件覆盖所有供应商和接口。
- 所有媒体模型均可真实生成、正确计量并在生产安全运行。
- 新备份已经能完整恢复当前数据库、媒体和应用。
- v36 已在用户原工作台运行，或 macOS 包已签名、公证、净机通过。
- 单机分服务部署已经具备高可用、PITR、异地灾备或明确吞吐承诺。
- 第二真实产品、真实商业付款或云端 Agent 已完成验收。

## 4. 交接资产

| 类别 | 应交付内容 | 保存范围 |
| --- | --- | --- |
| 源码 | 当前分支、公开未提交内容、锁文件、迁移、源码清单与版本摘要 | 仓库／受控交付包 |
| 设计 | 架构、功能合同、迁移设计、未完成方案及已作决定 | `docs/superpowers/` 和本手册 |
| 制品 | wheel／桌面 ZIP、provenance、文件库存、依赖许可证与 SHA | 制品库／受控本地目录 |
| 基础设施 | 主机、服务、端口、域名、证书、私有隧道、数据路径和重启策略 | 公开结构 + 私有实际配置 |
| 数据 | 权威库、媒体 registry、用户工作区边界、未决任务与资金摘要 | 私有数据库／配置清单 |
| 备份 | 密文、清单、密钥恢复路线、验证收据、失败目标与保留策略 | 受限存储，密钥分开 |
| 权限 | 独立账号与角色、管理员审批、撤权与凭据轮换流程 | 私有维护资料；不在手册写密码 |
| 验证 | 原命令、退出码、版本哈希、实际范围和失败／未知项 | `docs/validation/`／安全回执 |

当前 HEAD 不包含全部开发内容。若交接源码，必须先筛出本分支未跟踪的公共代码，排除 outputs、用户配置、会话、业务数据库与秘密，再生成完整清单。不要简单把整个工作目录压缩后公开。

## 5. 一次正式发布的签收清单

- [ ] 本次需求范围、版本和目标平台已确定；未完成项明确保留。
- [ ] 源码、依赖、前端 receipt、运行时来源和制品哈希一致。
- [ ] 对应范围测试及独立审查有本次终态；失败没有被旧通过结果覆盖。
- [ ] 订阅与自定义两条渠道可用，模型／推理能力不虚报。
- [ ] 登录、历史、草稿、附件与接口配置升级前后连续。
- [ ] 真实模型、工具、产物下载／解码和钱包差额已对应原操作核对。
- [ ] 取消、断流、刷新、未知费用和待核算准入按合同处理。
- [ ] 生产迁移、数据权限、唯一写入权威及失败恢复计划明确。
- [ ] 完整当前范围备份／恢复与容量门已验，不以文件新鲜度代替。
- [ ] 管理端私有，数据库不暴露，客户端没有中央供应商密钥。
- [ ] macOS 目标设备、签名公证与发行边界按交付等级如实记录。
- [ ] 本次发布、数据变更、Git 合并和推送分别获得对应指令并留下回执。

## 6. 建议维护的指标

后续运行看板建议至少记录：登录完成率和错误类别、目录可用性、模型首段延迟与完成延迟、上游错误／未知比例、在途／待核算数量和年龄、可信结算恢复耗时、预留占用、媒体字节／GC、备份新鲜度与实际恢复耗时、磁盘／内存／连接容量。当前未部署完整指标体系，不能虚构已有 SLA 或统计值。
