# Easel 自定义接口与订阅点数渠道修订设计

日期：2026-10-22。分支：`codex/ui-redesign`。状态：用户需求已澄清；本文件为修订设计，尚未实施商业支付或中央点数服务。本轮只读核对代码并新增本设计，不修改现有接口配置、不部署服务、不合并主分支。

## 1. 已确认的产品结果

用户保留原有自定义接口；另外增加平台订阅渠道。订阅用户注册登录、购买套餐取得点数后，可直接使用平台开放的模型和功能，无需配置各供应商／New API 的地址、API Key 或模型映射。服务端按对应功能或接口的费率扣点。

后续多个产品共用账号和有权使用的同一钱包；Easel 是第一个接入产品。身份延续此前 Logto 方向，业务权限、会员、订单、钱包、计量和账本归中央服务。国内正式支付接入**微信支付＋支付宝**，由用户在本轮明确选择。首阶段部署验收目标延续现有 4 核 4 GB 服务器，保留扩展能力。

“所有接口”落实为 Easel 的对话／Agent、图像、视频、音乐、转写、配音及已接入声音工作流统一取得平台授权与计费，不要求订阅用户逐项配置。平台后台目录区分待验证、开放、停用；未完成供应商或协议验收的能力不得显示可用，不能通过让订阅用户填自己的 key 来补齐。

## 2. 当前实现与差距

已核对的实际代码：

- `easel_platform/` 是 SQLite 开发账号及文本 Responses 服务。已有注册登录、设备会话、测试 plans/grants、原始 token 预留／结算／待核算；它没有正式点数钱包或订单支付。
- `easel/service_contracts.py`、本地平台桥与 harness 已有 custom/subscription 分流和订阅任务短期凭证，可沿用隔离规则。目前订阅仅支持本地 Codex 文本。
- `PlatformAccountSettings.tsx` 仍展示测试账号、测试权益、tokens，并要求填写平台服务地址；须升级为正式产品入口。
- 上一批 `MediaGatewaySettings` 是自定义接口的集中设置工具，用户仍需填写地址／业务 key。它应保留在自定义模式的高级设置中，不承担订阅服务入口。
- Logto、独立 PostgreSQL 中央服务、多产品 Scope、共享点数的详细方案已经存在，但实际 `services/platform/` 尚不存在。不能将设计或测试权益标为已实现的商业订阅。

## 3. 实施路径选择

| 路线 | 收益 | 代价 | 选择 |
| --- | --- | --- | --- |
| 中央账号、订单和共享钱包；Easel 使用产品会话；网关作为执行适配器 | 满足跨产品统一账号、点数及无配置体验；可替换执行网关 | 需要建设中央数据库、支付与任务账务 | 推荐并延续已确认方向 |
| 基于 New API 用户／额度直接组织全部会员与产品 | 可以复用现有部分运营能力 | 多产品会员、点数批次、订单发放及功能账务仍需补齐并明确唯一权威 | 作为内部执行与对账组件使用 |
| 在 Easel 本地增加套餐和余额存储 | 界面改动集中，开发预览简单 | 本机不能成为可信付款与跨设备共享余额权威，仍需中央服务 | 仅用于独立合成测试，不作为商业发行方案 |

中央控制面采用既有独立 Python／PostgreSQL 设计。模型执行优先复用已验证的适配器和现有 New API 能力；具体能力可以直连供应商或经内部网关，用户体验一致。本轮不重新决定全部供应商数据面的技术栈，不预设重写所有插件。

## 4. 客户端界面与来源规则

设置页顶层明确提供**自定义接口／订阅服务**两个渠道。选择订阅一次后，对平台已开放的全部能力生效，不再逐项打开“统一网关”。Agent 引擎与本机／云端执行位置继续是独立设置，订阅不隐含已经实现云端执行。

### 自定义接口

保留现有供应商、媒体统一网关、高级参数、自测及本地配置。不要求平台账号；不扣平台点数。平台故障、未登录、订阅到期或点数不足不会修改自定义配置。用户明确选择自定义时，才按自己的供应商条件和费用使用。

### 订阅服务

普通发行版由产品配置预置正式平台入口，用户界面显示登录／注册，无需输入服务地址。自托管地址仅在明确的开发／高级入口配置；已登录时更换平台须先退出。

- 未登录：显示登录／注册、套餐入口与能力说明。
- 已登录但未购买：显示真实套餐、价格、点数、有效期、可用能力、购买按钮。
- 已开通：显示当前套餐、到期日、可用点数、冻结点数、待核算金额／数量、购买或续订和消费明细。
- 点数不足／权益到期：提交前明确提示，提供购买入口；不自动改用自定义 key。
- 平台暂不可达：显示暂不可用，保留已选来源；未知余额不能显示成 0。

模型目录、默认模型、支持参数及费率由服务端下发。普通订阅用户看不到供应商密钥；可在已开放目录中选模型或使用平台默认推荐。已有 `NEW_API_*` 自定义值不上传到中央。

## 5. 登录、会员和共享钱包

沿用 [Logto 中央会员设计](2026-10-16-logto-central-membership-design.md) 的托管登录、本机一次性交接、产品设备会话与完整 Scope。Logto 只负责身份；套餐、点数和消费授权由中央服务负责。

个人账户先拥有个人 tenant 和 billing_account；未来团队钱包与个人钱包分别授权。同一有权钱包跨产品消费，产品和租户明细独立。服务端从已验证会话构造用户、产品、租户与钱包，客户端不能指定他人钱包。另一个产品共用 SSO，不复制 Easel 的 bearer。

点数使用整数 microcredits 存储，沿用 1 点 = 1,000,000 内部微点的设计；这只是精度单位，不定义人民币兑换价格。API 返回十进制字符串，避免浮点累计误差。原始 tokens、图片数、字符、音视频时长另存，按发布的费率版本换算。

套餐版本包含价格、币种、点数数量、会员时长、点数有效期、覆盖产品、能力与并发。未配置真实商业条款的套餐不能购买，不在代码中编造价格或标记已付款。首个正式套餐以覆盖已开放的 Easel 能力为目标；新增产品是否纳入旧套餐由版本条款明确决定。

## 6. 微信支付与支付宝

默认首版是**用户主动购买／续订**，每笔成功订单取得对应期间的权益和点数。自动扣款／免密续费需要额外支付产品签约及授权，不能由“订阅”一词隐式开通。

统一业务流程：

1. 用户选择已发布套餐和支付方式，中央创建订单，冻结套餐版本、价格、币种、点数和权益时间规则。浏览器不提交可信价格或发点数量。
2. 支付适配器按商户已开通的支付产品创建交易。桌面浏览器优先支持扫码收银台；是否使用微信 Native／支付宝当面付等具体产品，在商户能力核对后确定。
3. 客户端只展示收银台并查询中央订单状态。支付页面跳转、用户点“已支付”或本地 HTTP 请求均不能确认付款。
4. 中央对渠道通知验签，验证商户、支付应用、订单号、金额、币种和最终支付状态；通知不确定时按渠道规则主动查单。原始事件进入鉴别、去重的支付 inbox。
5. 支付确认与订单状态、会员周期、点数批次、平衡分录和 outbox 在数据库事务内处理。外部交易号、支付事件及发放来源均有唯一约束；重复／乱序通知不重复发点、不延长同一周期。
6. 客户端刷新余额和权益后即可使用全部已开放能力，无需任何供应商配置。

支付订单与退款必须支持查询和对账。退款由权限受控流程发起，记录新的补偿分录并按实际会员／点数消耗规则处理，不能删除原订单或消费历史。对已消费点数的退款规则必须在套餐商业条款和退款方案中明确后开放。

实际商户号、应用、证书／公钥和私钥、回调域名等仅通过服务端安全部署配置提供，不放入仓库、普通用户页面或聊天。开发验收先使用隔离的支付事件夹具／适配器测试；商户环境接入后另行验收真实扫码、查单、到账和退款。

## 7. 按功能与接口扣点

中央按能力提供价格目录，覆盖文本 token、图片数与规格、视频时长／分辨率、音乐任务、配音字符／音频时长、转写时长和声音登记操作。不同模型可以有不同费率。

一次收费操作先由服务端取得费率和有界用量上限，原子预留点数，再调用供应商。完成后按可信使用事实结算，释放差额。对于固定价任务，成功收费依据为目录定义的固定交付单位；不伪造 token 或时长计量。

多步骤功能以一个 invocation 关联若干收费子操作，每个实际操作只结算一次。用户可查看总计和子项；初始方案不叠加未声明的额外“功能费”，本地文件读写、轮询和同一产物下载也不重复扣生成点数。正式功能打包价如需增加，应单独发布计费规则并明确覆盖哪些操作。

```text
请求 → 验身份／权益／能力 → 冻结费率与预算 → 原子预留
     → 执行／持久任务 → 可信结果与计量 → 实际扣点＋释放差额
```

钱包不能负数；两个产品同时消费同一个钱包必须在 PostgreSQL 中竞争同一原子预算。点数余额、预留、已用、到期和发放来源通过不可变平衡分录与点数批次核对。

未发送即可取消的任务释放预留。已发送但完成和费用未知的任务进入待核算，不能直接按 0 退款或盲目重发；供应商确定失败与平台补偿按已发布规则记新分录。同步断流、视频异步轮询、回调和下载共用同一任务／reservation。

幂等范围包含钱包、产品、操作和稳定调用键。同键同内容返回原订单或任务结果，同键不同内容拒绝。无法证明原生自动重试携带稳定键的路径必须单独验证，不能承诺所有重试天然免费。

## 8. 服务端与执行网关边界

| 组件 | 管理内容 |
| --- | --- |
| Logto | 统一账号、登录、验证、恢复和 SSO |
| 中央平台 | 产品／租户、会员、订单、支付、共享钱包、计费费率、正式点数账本 |
| 模型／媒体执行层 | 供应商适配、渠道选择、上游请求、持久任务、产物和可信用量 |
| Easel 本地桥 | 私有会话、按任务取得受限授权、来源隔离、用户界面 |

New API 可继续作为内部执行渠道，供应商 key 与网关业务凭据由服务器持有。用户客户端只拿产品／任务授权，不拿长期 New API key。New API 的内部限额与日志用于执行预算和对账，中央点数为唯一用户可花余额，不能维护两套彼此独立的正式用户钱包。

如果媒体脚本在本机调用中央 API，应使用绑定产品、用户、钱包、能力、期限和预算的短期任务凭证。不能把它写入用户的持久 `NEW_API_KEY`，也不能仅靠跳过客户端表单来冒充已实现中央授权。

## 9. 分批交付与完成门槛

这次修订将支付与媒体纳入订阅目标，取代“测试会员＋单条文本链路就结束”的旧完成定义。实施分为以下子项目，每批独立验证：

| 批次 | 具体交付 | 验收门槛 |
| --- | --- | --- |
| S1 中央基础与钱包 | 独立服务／PostgreSQL、Logto 身份接入、完整 Scope、套餐与价格版本、共享点数账本 | 两合成产品共享同钱包但 bearer 独立；并发不超扣；旧 token 账本不冒充正式点数 |
| S2 购买闭环 | 微信／支付宝适配接口、套餐订单、支付 inbox/outbox、确认发点、订单与明细 UI | 测试事件覆盖成功、错误金额、假通知、重复／乱序、查单恢复、幂等发点、已付订单重复支付、关闭订单晚到支付、重复／乱序退款通知及退款与消费并发；补偿不删历史、不产生负钱包。未接真实商户不显示收款已验收 |
| S3 统一订阅调用 | 对话和媒体统一能力授权、价格查询、预留、结算、持久任务及产物 | 文本、同步图片、异步视频先组成三种完整范式作为中间验收；音乐／转写／配音／承诺的声音工作流逐项完成后才算本批全量交付，三种范式通过不能宣称全部接口可用；未完成的能力显式待开放 |
| S4 Easel 用户体验与迁移 | 顶层两渠道、预置入口、登录／购买／余额与明细、取消／不足点数体验、自定义高级配置归位 | 浏览器端不填供应商 key；使用扣点可核对；来源切换不覆盖原配置；旧账号迁移不重复发点 |
| S5 部署与真实验收 | 现有 4 核 4 GB 隔离部署、真实 Logto／商户／供应商配置、对账和故障恢复 | 小额真实支付与退款、逐类真实产物及用量、两产品并发钱包、资源和恢复结果分别记录；仅通过已验收能力进入正式目录 |

S1／S2／S3 服务合同应先固定；不能先做一个显示“购买成功”的空壳。前端与单元验证可以并行，但真实扣款、生产迁移和上线要在可审阅交付及实际环境具备后单独执行。

## 10. 验证清单与当前状态

后续必须验证：未登录／无权益／不足点数拒绝；自定义匿名使用；支付成功才发点；重复回调不重复发点；一个任务只结算一次；跨产品并发；费率版本冻结；未知结果保留待核算；到期与退款分录；跨账号／租户任务和产物拒绝；密钥不进入前端／日志／发行包；中央不可达不自动使用自定义接口。

本文件的当前证据来自源码与已有历史报告核对，没有运行本轮应用测试，没有实现上述中央、支付或点数代码。上一批 376 后端／144 前端测试只属于自定义统一配置交付，不作为本方案商业订阅的通过证据。当前分支和用户既有改动保持；不修改真实 `.env` 或真实账号数据。
