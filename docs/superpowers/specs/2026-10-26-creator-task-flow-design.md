# Easel 普通创作者任务体验改造方案

状态：供确认的完整方案草案；本文件不代表已实施。

日期：2026-10-26。

目标：让不理解模型、Agent、API 的个人创作者，能够表达需求、补充素材、执行任务、处理异常、继续修改，并取走可用内容。

评审依据：[2026-10-26 实测报告](/Users/jiandan/.codex/visualizations/2026/10/26/01a1775c-8209-70a0-aabb-64789ff15f07/easel-review/评审报告.md)。本方案提出的交互和字段均为改造目标，不能当作当前已具备的行为。

## 1. 决策与边界

推荐采用“保留布局，修通任务路径”的渐进改造。

| 方案 | 收益 | 代价与缺口 | 决定 |
|---|---|---|---|
| 保留现有三栏，统一任务状态、草稿和成品操作 | 直接处理本轮实测断点，兼容已有使用习惯，可分批验收 | 需要少量前后端契约补充及状态整理 | 推荐 |
| 只改首页文案、视觉和按钮样式 | 局部工作量小 | 不能解决发送被禁用、草稿消失和结果取不出 | 不作为主方案 |
| 改成全屏向导，重新组织所有导航 | 首次体验可能更聚焦 | 影响熟练用户与现有布局，重做范围大，收益缺少用户证据 | 本轮不采用 |

保留当前桌面“左侧工具栏—中间对话历史—右侧创作区”的结构；首页沿用当前页面框架，成品仍在右侧创作区内查看，不增加常驻第四栏。窄屏沿用历史入口与单工作区展开方式。

本轮处理：入口就绪、草稿及附件引用持久化、任务生命周期、原任务恢复、成品复制/下载、预览返回、关键路径无障碍、上线兼容性。

本轮不扩展：新模型接入、新 Agent 体系、云执行、中央账务规则、自动发布、跨设备同步、全新文件版本系统、导航全面重分类、主题重做。现有自定义来源、中央订阅、旧订阅的账号和权限边界继续由后端决定。

目标人群暂不调整。首次成功定义为“产出一份符合要求且用户能取走的内容”；看到回复或看到文件链接都不单独算成功。后续修改成功要求原任务上下文可用、修改结果可辨认、取走内容正确。

## 2. 用户路径与界面职责

主路径：进入工作台 → 写下要完成的内容 → 按需补充信息/素材 → 提交 → 理解处理状态 → 看成品 → 在同一对话提出修改 → 复制或下载。

| 区域 | 承担的职责 | 本轮调整 |
|---|---|---|
| 工具栏 | 到达已有功能与设置 | 保留功能与分组，所有入口可键盘访问；账号连接不作为普通写作的前提 |
| 对话历史 | 找回正在做及做过的内容 | 保留标题、归档等能力，补充处理中/待补充/待确认/已完成的简短文字状态；不只靠颜色 |
| 右侧创作区 | 表达要求、补充、看过程和结果 | 输入框、就绪提示、任务反馈和成品操作共用同一会话上下文 |
| 内容库 | 找到已有成品和素材 | 现有预览加入复制/下载，保留返回来源；不要求用户理解深层目录 |
| 账号与订阅设置 | 配置和查看详细账号/费用信息 | 保留详细页，任务内提供针对该原请求的查询入口，避免要求用户手工找记录 |

首页首屏的推荐顺序：简短问候 → “今天想完成什么？”输入区 → 一条上次任务/最近成品入口（有数据才显示）→ 现有经营统计、热点和排期。

欢迎图保留，但收窄到不挤压创作入口；不更换主题。四张经营统计移至输入区之后并降低视觉权重。没有证据要求删除统计或任意一个工具入口。

输入标签：“今天想完成什么？”

示例占位：“例如：为周末旧书市集写一篇小红书文案，语气轻松，200 字以内。”

辅助说明：“可以先说想法，也可以添加图片或文档。缺少关键信息时，我会继续问你。”

空输入的主操作为“进入创作”，只打开空对话；有输入时为“开始创作”，通过统一提交入口执行。点击示例只填入输入框，用户仍可修改后提交，不立即调用模型。服务未就绪时两种入口都保留草稿、明确说明下一步，不把非空要求绕过校验发送。

默认沿用当前合法的创作画像、服务来源和已配置模型。未配置时引导当前已有的必要设置；不擅自切换订阅/自定义来源、不静默更换模型、不推荐未经验证的“更快/更便宜/更好”标签。发布账号只在用户执行发布时出现必要提示。

## 3. 创作输入与补充信息

首页和对话使用同一份输入状态和同一套提交校验，首页提交后转入对应对话。输入框持续可见的标签为“创作要求”或“继续修改”，占位文字不承担唯一标签职责。

素材操作统一称“添加素材”。上传过程中逐项显示文件名和状态：上传中、已添加、上传失败、需要重新添加；失败可只重传该文件。用户移除素材只取消草稿引用，不在无说明时删除磁盘文件。

只询问完成当前任务不可缺少的信息。例如旧书活动文案缺时间地点时，优先合并询问“活动时间和地点是什么？”；不要求先填写完整画像、模型参数或发布账号。可选的风格、语气、长度可沿用用户已有设置或清楚列出假设。无法确认的事实不得由模型补造。

第一批复用已有 QuestionCards 和普通对话补充能力，不建立覆盖全部技能的固定表单系统。已支持结构化问答的路径显示就地问题；不支持的执行引擎通过普通追问补充，不把普通文本误标为“需要你操作”的系统状态。

执行中允许用户继续写下一条草稿和添加下一轮素材，但同一会话不并行提交下一轮。提示：“当前任务仍在处理，你可以先写修改要求，完成后再发送。”不自动排队发送，不因任务完成自动提交草稿。

Enter 发送、Shift+Enter 换行；中文输入法确认候选词不得触发发送。发送不可用时，输入框仍可编辑，旁边说明具体原因，而不是仅给灰色按钮。

## 4. 就绪状态：一套规则覆盖所有入口

就绪状态与任务状态分开。后台“CLI 已安装”或“API 已配置”不能被当作已完成一次真实模型验证；界面只承诺“可以提交”，不承诺供应商必然成功。

| 状态 | 输入区显示 | 主操作 | 行为 |
|---|---|---|---|
| 正在检查 | 正在连接创作服务，内容可先填写 | 暂不可提交 | 可编辑与保存草稿；不先显示离线或空数据 |
| 可以提交 | 可开始创作 | 开始创作/发送修改 | 使用当前合法选择，无额外推理探活 |
| 目录后台刷新，旧选择仍在有效租期 | 正在更新创作服务状态 | 仍可按有效快照提交 | 只在后端验证仍允许时成立；不延长过期租期 |
| 租期过期或网络不可确认 | 暂时无法确认创作服务，输入内容已保留 | 重新连接 | 不静默发送，不显示“未扣费”等未知事实 |
| 未完成必要设置 | 完成创作服务设置后即可开始 | 去设置 | 跳到相关现有设置区，返回后草稿还在 |
| 需要确认模型 | 当前创作设置已变化，请重新确认 | 确认选择 | 就地打开有上下文的选择器，不要求用户找原因 |
| 身份或渠道变化 | 当前账号/服务已变化，原对话已保留 | 查看原对话 / 使用新账号新建 | 禁止把旧上下文和待执行请求静默交给新账号 |
| 前后端不兼容 | 工作台服务版本需要更新，草稿已保留 | 查看恢复方法 / 重新检查 | 阻断新增执行；仍允许访问可用的历史和成品 |

模型选择器保留实际模型名和推理设置，作为可选高级操作。默认不让用户在进入创作前做不必要的技术选择。

刷新模型目录时区分 catalog_revision（短期目录快照）与账号、渠道、供应商配置等 authority/source 信息。只更换目录快照、模型与权限未变时，可以用新快照重建合法选择；模型消失、权限/来源变化时不能自动续用。后端对最终请求继续校验，前端显示的模型名不构成执行许可。

## 5. 草稿、附件和位置必须连续

一份草稿归属于一个工作区范围和一个会话，包含文本、附件引用、更新时间、修订序号及提交关联。按现有存储模式增量扩展，不引入新的全局状态框架或数据库。

拟定 DraftEnvelope v1 的最小字段：scopeKey、sessionId、revision、text、attachments（服务端返回的 ID/路径引用、显示名、大小、可用状态）、updatedAt、submission（clientTurnId、submittedRevision、确认状态）。其中 scopeKey 由后端给出非敏感工作区标识，并叠加适用的账号/服务来源范围；不把密钥、令牌、认证文件或原始凭证放入浏览器草稿。账号/来源变化时草稿保持原归属，仅允许用户明确选择是否复制文字到新会话。

保存策略：输入变更后短延迟写入（目标 300ms），在切页、切会话、提交和 pagehide 前同步刷新当前 revision。成功写入后才能显示“草稿已保存”；存储失败显示“草稿暂未保存，请复制备份”，仍保留内存内容。持久存储不可用时，对主动离页给出说明，但不能承诺浏览器崩溃恢复。

草稿提交采用快照：revision r 提交后，与 clientTurnId 关联并暂时保留；只有服务端给出“已接受该请求”的可校验确认，才清除 revision r。用户在此期间输入的 r+1 不能被较早回调清除。HTTP 连接成功、泛化的“已收到”动画、模型目录检查成功都不能代替提交确认。

如果提交确认丢失，显示“正在确认是否已提交”；先按原 clientTurnId 查询，不能自动生成新 ID 重发。可靠确认未提交后，允许继续使用原草稿提交。上传文件成功不等于草稿引用已经保存。

切页/切会话/预览/刷新后，恢复文本、素材、会话、产物位置及必要滚动锚点。附件引用恢复后由后端校验归属、文件存在和访问范围；失效的文件保留 chip，显示“需要重新添加”，用户可移除或替换，不会悄悄漏带。

浏览器 URL 记录页面和稳定会话 ID、产物不透明标识；不在 URL 放正文、密钥或工作区绝对路径。采用现有单页应用可兼容的 hash 路由，支持旧 #/outputs/... 链接转换，不要求服务端重写所有路径。浏览器前进/后退必须与页面状态一致，产物预览关闭返回调用来源及焦点。

刷新时优先恢复 URL 指定上下文，其次是本标签上次位置；不一律回工作台。跨标签继续复用现有会话占用防护，不能为恢复草稿而破坏并发隔离。真实不同 origin 的浏览器数据不在本轮自动跨端口迁移。

## 6. 任务反馈与失败恢复

任务对用户显示目标、当前可确认阶段、是否需要操作和最近成品。技术日志保留在“查看处理详情”中，不默认把 commandExecution、内部技能 ID、绝对路径摆在主反馈里。

只从真实结构化事件映射阶段；没有事件证明正在读取素材时，显示“正在处理你的要求”，不依据自然语言片段猜阶段。没有可靠进度时不显示百分比、预计剩余时间或虚构“未卡住”保证。

| 任务状态 | 默认文案 | 可用操作与约束 |
|---|---|---|
| 草稿 | 草稿已保存 · 1 份素材 | 发送、继续编辑、移除引用 |
| 正在提交 | 正在提交创作要求… | 防重复点击；保留快照 |
| 已接受/正在处理 | 正在处理你的要求。可切页，任务会继续 | 查看详情、请求停止；继续写下一轮草稿 |
| 有依据的阶段 | 正在读取素材 / 正在生成修改稿 / 正在保存文件 | 只显示后台有证据的阶段 |
| 等待补充 | 还需要你补充活动时间和地点 | 在当前会话回答；已有内容和附件保留 |
| 结果已完成 | 已完成，文案已保存 | 打开成品、复制、下载、继续修改 |
| 有回复但文件未确认 | 回复已生成，尚未确认成品文件 | 复制回复、查看详情；不能显示“文件已保存” |
| 正在停止 | 正在停止，已有内容会保留 | 防止重复停止；不能提前宣称后台结束 |
| 已停止 | 已停止，已生成内容保留 | 查看已产出内容、编辑下一步；不承诺零费用 |
| 已确认失败 | 本次生成未完成，已保留要求和素材 | 查看原因；仅按后端判定显示可重新执行 |
| 连接中断/提交或结果待确认 | 连接中断，正在查询原任务 | 查询原任务、查看已收到内容；禁止自动重发 |
| 内容已完成，费用待确认 | 内容已完成；费用仍在核对 | 正常查看/取出内容；查询该原请求费用，不阻断取回 |
| 结果不可再取回 | 该次结果缓存已过期；现有本地文件仍可查看 | 展示实际可用文件；重新执行是新的明确请求 |

执行、交付、文件可用性、账务状态分别记录，不能把 done 简化为“成功并已结算”，也不能把 clean_end=false 一律当供应商失败。停止、超时、未知和部分输出需保留实际原因。进程存在/本机转发完成不能替代中央终态。

重试交互去歧义：

- “查询原任务”：只读查询/续接同一 ID，不调用模型，不再次提交。
- “重新连接”：刷新可执行状态，不调用模型。
- “修改后发送”：在原对话新增一轮要求，保留先前消息和成品。
- “重新执行”：明确创建新任务；如果适用，说明会按新请求计点。先前记录不因新执行被覆盖。

中央订阅的待确认请求复用现有执行恢复记录和所有权检查，查询入口直接出现在对应任务旁。可复用现有列表接口后按本机已知 invocation/operation 关联筛选；不得按模型名或“最新一条”猜关联，也不跨账号展示。旧记录无法关联时保留现有设置查询入口并说明限制，不伪造绑定。

后台模型失效的下一步分开：可恢复网络给“重新连接”，缺配置给“去设置”，模型已撤下给“选择可用模型”，结果待确认给“查询原任务”。技术错误代码保留在可复制的诊断详情里，不含凭证。

## 7. 成品查看、修改与交付

优先把现有文本文件取出动作补齐，不建设新内容管理平台。

成品区域最少包含：可读文件名、生成/修改时间、已确认的保存状态、主操作“复制文案”、次操作“下载文件”、辅助“继续修改”和“在内容库查看”。本轮沿用文件名和时间区分原稿/修改稿；只有当前执行确实保留了原文件且可校验时显示“原稿已保留”。不假设任意 Agent 写文件行为天然提供版本保护。

对本次目标的文本修改默认要求另存新文件；结果验证确认新旧文件存在，必要时检查原稿哈希后才显示保留成功。没有文件证据时只称“修改回复”，不把模型声明当成文件系统事实。不依赖新增完整版本系统兑现这一条路径。

复制动作：从实际文档加载可交付文本，不复制模型执行旁白、内部路径或状态信息；明确区分“复制文案”和“复制回复”。对于内容不透明或无法可靠提取的格式，提供“复制原文”或下载原文件，不承诺无损富文本转换。只有剪贴板写入成功后才显示“已复制”；失败提示用户选择文字复制。

下载动作：复用安全媒体/文件路由，设置合适文件名与下载响应；原件存在即可下载，不依赖预览解析成功。页面可以报告“已开始下载”，不能仅因为点击按钮就宣称系统文件已经保存。浏览器自动验收检查实际下载与文件哈希。

继续修改动作：返回来源会话，在输入框提示“正在修改：小红书文案_修改版.md”，把目标作为结构化文件引用绑定到下一轮，不要求用户手写绝对路径。输入框不预先写固定修改内容，不自动提交。来源会话不可用时明确提供“以此文件开始新对话”，不能假装上下文仍在。

产物关联优先使用执行引擎给出的结构化文件引用；兼容当前路径时，后端校验消息中明确引用的 outputs 文件，返回已验证的文件标识和可访问状态。不得扫描全盘、挑最新文件或按文件名猜属于本轮。旧消息按需读取解析，保留原文不改写。

预览失败时仍保留标题、文件状态、下载、返回；给“重新加载预览”。不存在、失效、无权限必须分开；不能为了让复制/下载看似可用而绕过现有路径和权限检查。删除移入次要操作，保留现有不可恢复删除确认，不新承诺回收站。

## 8. 视觉、文案和无障碍规则

每个上下文明确一个主要下一步：未开始时“开始创作”，需要补充时“提交补充”，完成时“复制文案”，故障时“查询原任务/重新连接”。其他功能保留，但不与当前目标争夺同等权重。

建议用户可见术语：对话→创作对话；产物→成品；模型/推理强度仍在高级选择里保持真实名称；画像保留现有入口，并用说明“默认写作偏好，可稍后设置”解释；Agent/CLI/API/执行引擎只在连接设置和诊断详情出现。此处的“创作对话”先用于页面标题与说明，导航重命名需结合小样本验证，不强制整站一次性替换。

加载、空、失败三套文案：加载“正在读取最近成品…”；真空“还没有成品，开始第一条创作”；失败“最近成品暂时无法加载”，提供重试。不把空数组和异常都解释为没有数据。热点不可用时说明“不影响当前文案创作”，仅在能力判定确实如此时显示。

无障碍验收遵循 WCAG 2.2 AA：关键路径键盘全可操作，文件卡片使用链接/按钮；焦点清楚可见且不被固定输入区遮挡；表单有持久标签；状态消息就地可被辅助技术感知，但不逐 token 播报。模态预览具备对话框名称、适当初始焦点、Tab 范围、Escape 关闭、背景不可交互、关闭归还焦点。使用成熟可用的现有模式，不仅添加 aria-modal 就宣称通过。

普通文本对比度至少 4.5:1，大文本按标准至少 3:1；必要的组件和焦点视觉按标准检查。点击目标按 24×24 CSS px 门槛与适用例外验收，主要触摸操作建议更宽松，但不把 44px 误写成 AA 一刀切要求。320 CSS px、200%/400%缩放、文本间距、VoiceOver、中文 IME 和 reduced-motion 都进入真实检查；复杂文档预览可能适用的二维布局例外需单独记录，不拿例外放过创作输入区。

外部依据：

- [Nielsen 可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)：将系统状态、用户语言、控制与错误恢复落实到本路径。
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)：关键路径的可测试无障碍要求。
- [WAI 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：预览焦点、背景交互与关闭行为。

## 9. 数据、接口与技术落点

沿用 React/TypeScript 前端、FastAPI、本地会话与 jobs 事件、现有中央执行恢复接口。不引入新路由库、状态框架、队列或业务数据库；先用小范围状态模块从 App 中抽出这条路径的规则，避免扩大到全仓重构。

以下是拟议契约，不是当前已存在 API：

| 契约 | 最小内容 | 兼容策略 |
|---|---|---|
| 扩展 GET /api/status | 后端构建标识、前端契约兼容范围、非敏感 workspace scope、可用的任务/产物契约版本 | 新字段增量；旧后端缺字段时进入“需更新/无法确认”，保留草稿和可读历史，不绕过模型校验 |
| 提交确认事件 | clientTurnId、会话 ID、accepted/拒绝、实际 route、接受时间 | 后端在验证并持久记录该轮后发出；泛化 activity 不算确认；重复 ID 需核对内容摘要并拒绝不一致，不重复下游分发 |
| 原任务查询 | 按会话及精确 turnId 查询接受/执行/结果可用性 | 复用现有 last 的匹配校验和 jobs 事件；增加有界单任务状态读取。无法确认不存在不等于未提交 |
| 任务结果摘要 | turnId、状态、clean_end/stop_reason、已验证文件引用、适用的中央关联键 | 不破坏已有 text/status；适配器逐步补充，未知字段按未知处理 |
| 文件读取/下载 | 可访问的文件标识、显示名、内容类型、存在状态、下载 | 复用已有安全路由；新 ID 不泄露根路径，也不替代权限校验；旧 outputs 链接继续可读 |

推荐模块与职责（拟新增文件实施前再次检查命名冲突）：

- `web/frontend/src/lib/workbenchReadiness.ts`：统一就绪与模型选择保持规则，输出用户可见阻断原因。
- `web/frontend/src/lib/composerDrafts.ts`：草稿 envelope、提交快照、存储异常与范围隔离。
- `web/frontend/src/lib/workbenchNavigation.ts`：页面/会话/产物 URL 解析及旧链接兼容。
- `web/frontend/src/lib/taskLifecycle.ts`：accepted、running、stopping、terminal、unknown 及恢复动作判定。
- `web/frontend/src/components/TaskStatus.tsx`：输入区旁和任务内的可操作状态提示。
- `web/frontend/src/components/DeliverableActions.tsx`：实际文档复制/下载与反馈。

已有主要修改点：App.tsx、DashboardPage.tsx、ChatPage.tsx、ComposerModelPicker.tsx、ConversationSidebar.tsx、OutputsPage.tsx、ArtifactGallery.tsx、MessageBubble.tsx、lib/store.ts、lib/api.ts、相关主题 token、web/app.py、easel/chat_models.py、服务打包源清单策略和既有中央恢复组件。最终边界按本批任务确定，不一次性改完所有列表文件。

## 10. 分批实施、验证和发布

| 批次 | 交付 | 通过才进入下一步 |
|---|---|---|
| A：可执行与恢复 | 版本识别、统一提交门槛、输入区原因、模型重选规则、提交确认与精确查询 | 首页与对话行为一致；故障可恢复；重复请求不分发；身份变化不越界 |
| B：内容与位置保留 | 会话草稿、附件引用、提交快照、路由返回、运行中续接 | 切页/刷新/返回零约束丢失；不重复上传或提交；新输入不被旧回调清掉 |
| C：成品可带走 | 文档复制/下载、来源返回、就地修改目标、预览键盘完整 | 复制内容正确；下载原件一致；键盘全路径可完成；无文件不假称已保存 |
| D：首次体验与状态表达 | 首页层级、加载/空/失败、目标阶段、技术详情收纳、必要补充提示 | 用户能开始、理解过程和下一步；没有新增阻塞式设置步骤 |
| E：组合验收与发布 | 真实路径、受控异常、可用性测试、主题/窄屏/打包对齐 | 本地、打包运行、浏览器、真实供应商/订阅分层出具证据；回滚不丢新数据 |

发布顺序：先上线增量兼容后端与任务记录能力，再发布匹配前端与打包产物。服务端先兼容旧字段，客户端再启用新交互；旧前端继续保留原请求安全边界，不能误用新记录。实际多部署环境由已配置部署方式决定，本方案不授权生产上线。

回滚保留旧会话、原始任务日志、草稿新命名空间和已生成文件。迁移采用读取旧格式、写入新版本 envelope，不原地批量改写用户全部历史。旧客户端不认识新格式时忽略新命名空间，不删除它；新版本恢复后重新读取。任何清理都不进入本轮自动流程。

## 11. 验收矩阵

工程硬门槛：

1. 同一要求从首页和对话提交，使用相同就绪判断和合法模型快照。
2. 旧后端/404/超时/断网有就地原因；不把“服务不可确认”说成“未扣费/未执行”。
3. 同一已接受 clientTurnId 重复连接/刷新只接回原任务；不同内容复用同 ID 被拒绝。
4. 三条修改约束、两个素材在切页/切会话/刷新/预览返回后逐项一致；新草稿不会被旧确认清空。
5. 工作区、账号、渠道变化不串草稿、不跨范围取回结果，不静默换模型。
6. 内容成功、取消、失败、结果待确认、账务待确认状态相互可区分；取消未确认时不提前显示已停止。
7. 成品复制不含执行旁白；下载文件与原件哈希一致；预览失败仍可下载存在的原件。
8. 从内容库仅用键盘打开、复制/下载、关闭、回来源会话并继续修改。
9. 真实 320px 重排、400%缩放、VoiceOver、中文 IME 与适用的主题对比度检查有证据。
10. 现有重试安全、账号归属、权限和路径访问限制不回退；前后端打包版本可识别。

用户验证：5 位符合目标假设的创作者，在授权后记录任务操作与原话。首次开始至少 4/5 在 60 秒内正确进入；素材与要求 5/5 完整保留；故障恢复至少 4/5 在 90 秒内完成且待确认零重复请求；刷新后取回正确修改稿至少 4/5 在 60 秒内完成。时间为改造验收门槛，不是现有统计。若失败原因是导航/术语，再调整层级；若是后台耗时/产物能力，则单独记录能力问题，不用换视觉掩盖。

没有真实用户测试前，首页排序和术语调整标为专业方案假设；工程硬门槛以真实操作与原始记录验收，不用主观总分替代。

## 12. 范围收口

本方案的完成条件是：用户不必理解内部架构，就能安全提交一次任务；要求和素材能保留；异常时知道原任务是否仍在执行；结果能取回、继续修改和带走。实施拆分见同日期的 creator-task-flow-rollout 计划。

本轮只新增方案文档。没有执行产品改造、生成任务、改动账号配置、提交 Git、重启服务或发布部署。
