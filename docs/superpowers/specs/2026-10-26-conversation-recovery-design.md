# 原对话中的中央请求状态查询

本批延续用户“继续下一步开发”的要求，收口 S3-B／R2 已有的只读恢复体验。沿用 `codex/ui-redesign`，不合并主分支，不自动提交或推送。不是实施整个待确认的 creator-task-flow 草案。

## 交付

新中央订阅轮次在消息旁提供“查看本次请求状态”。用户点击后，按服务端记录的精确会话和轮次查询全部对应的模型操作，分开显示本机转发、中央执行／费用、结果缓存。保留设置中的原查询入口。

## 关联与只读边界

`RunRequest.turn_id` 由 Web 接受的当前轮次传入。Pi／Codex 创建 ExecutionProxy 时传递 session_key 和 turn_id。代理在真实发送前的原私有操作记录中保存 `turn_key=SHA256([session_id,turn_id])`；不保存提示词、正文、凭证或账户明文。

`operation_turn_key(session_id,turn_id)` 校验两个标识均为 1–160 个受限 ASCII 字符，以字母或数字开头，其余仅字母、数字、点、下划线、冒号、短横线。只有完整关联才记录。旧调用没有 turn_id 时继续原记录格式，不回填或推测关联。

新增 GET `/api/platform/central/execution-recoveries/turn?session_id=...&turn_id=...`。复用当前认证 owner、真实 `/v2/me` 复验和原 operation GET。先按 owner 和 turn_key 筛选再取有界结果；每次最多 50 条、扫描和时间有界，截断明确显示。当前身份变化时整批结果拒绝，查询不写操作记录、余额、审计或任何供应商数据。

## 消息与界面

仅在服务端已接受中央订阅上下文后发送增量 `central_recovery` SSE 事件 `{version:1,turn_id}`，并进入原事件日志，断线续接时可重放。事件不含完整 Scope。旧客户端忽略未知事件，旧后端缺少事件时新客户端保持原体验。

前端只接受与当前请求 turnId 一致的提示，将 centralRecoveryTurnId 随助手消息持久化。成功、错误和停止均保留该轮次标识。卡片只在用户点击时查询；不自动重新生成、恢复工具或解除 uncertain-turn 防重发保护。没有可信关联的旧消息不生成假的“已查询”状态。

新版本的 running／done 快照也保存同一显式版本化 `central_recovery` 标记。事件日志不可用时，前端只有在该标记、快照轮次与中央路由同时匹配时才恢复查询入口；旧快照仅有 turn_id／route 不够。只有提示、尚无正文的停止也保留引用。

查询前后复验同一中央账号／钱包及 origin；登录、退出和账号变化使旧查询失效，旧异步响应不能覆盖新身份。页面切换和卸载取消本次读取。视图不持久化财务结果。

状态覆盖 reserved、dispatched、pending_reconciliation、settled、released、waived；unknown／not_found／unavailable／truncated 如实说明。`waived` 保持 actual=NULL、客户收费0、供应商用量未知。金额用 BigInt 十进制格式化。结果缓存存在不代表本地工具可安全重跑。

## 验证与发布

先验证精确关联、同轮次多个操作、默认旧记录兼容、跨账号／会话／轮次隔离、非法标识、损坏／符号链接文件、扫描截断、无供应商 POST／无文件写入。前端验证事件重放、错误和停止保留标识、状态文案及账号变化竞态。保留原重试安全测试。

构建新的本地桌面版本，备份并核对原 HOME、工作区、登录、配置与历史后更新 17868。中央服务无需迁移或发布。真实验收复用本人已登录账号，先验证 Pro 正常工具往返，再以客户端断开连接、后台继续完成的方式验证原轮次查询；不人为制造未知供应商费用，不自动重试结果未知的调用。真实渠道测试保留原收费授权和服务器内密钥范围。
