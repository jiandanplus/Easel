# N3 closed network profile contract (design frozen for independent review)

Scope: approved Route A only. No implementation or runtime PASS is asserted. N1 source SHA256 c000491d7a9d2fa12cb2242adc4006e4387069f34a772e5cea14d8e011158277 and N2 ee2aacb12fc7856fcdeccf63d7a452dacc33056394a29b44a2f8a770d6fc74c8 are the interfaces reviewed here. Bootstrap grantor remains separate. Root alone performs native observations.

## 1. API, authority and supported environment

Proposed pure API: `validate_network_profile(observation: NetworkObservation) -> NetworkProfileResult`. Exact frozen, repr-disabled dataclasses, no subclasses, dictionaries, callbacks, policy arguments, imports with I/O or filesystem policy selection. `NetworkObservation(kernel_release: str, byteorder: str, namespace_before: NamespaceIdentity, namespace_after: NamespaceIdentity, sysfs_before: tuple[SysfsEntry,...], sysfs_after: tuple[SysfsEntry,...], proc_before: ProcViews, proc_after: ProcViews, dumps: tuple[NetworkDump,...])`. NamespaceIdentity has integer device/inode; SysfsEntry is the closed InterfaceEntry(name,index,iflink,arphrd,flags,operstate,address_bytes) or ControlEntry(name,uid,gid,mode,file_type); ProcViews has exact bytes dev,addresses6,route4,route6,fib_trie. These objects are DATA, never origin credentials.

Result fields: profile_id, profile_sha256, security_sha256, canonical_security_json: bytes, observed_interfaces: tuple[str,...], active_interfaces: tuple[str,...], sysfs_controls: tuple[ControlEntry,...], raw_observation_sha256, telemetry_json: bytes. A constructed result cannot confer TargetHandle or VerifiedRestoreInput. N4 must call the validator itself on bytes acquired by its fixed reader/N2 and bind independent Root target provenance. Never accept a caller-supplied result/hash as authority.

Only release `6.12.76-linuxkit`, little-endian, is considered here. Release text selects no downloadable profile and is not vendor byte attestation. Other release/endianness rejects. Independently source-fixed profile ID `b3-linuxkit-6.12.76-inactive-v1`. Do not enable a second generic lo-only profile: no primary evidence here defines its differing AF_SPEC/sysfs/proc semantics. A lo-only or smaller inventory on this same release is unsupported by this first profile and rejects; a later separately reviewed source revision can qualify it without widening the approved device/route boundary.

Six dump slots, exactly ordered: (18,0,11),(22,0,12),(26,2,13),(26,10,14),(34,2,15),(34,10,16). Each exact NetworkDump must have the same positive u32 local_portid; re-run N1 parse_dump on original datagrams and re-run parse_message, require parsedmessages exactly equal reparsed messages (including types/bytes), never trust cached records. Aggregate raw dump limit 8 MiB, at most 256 packets/slot and 65536 bytes/packet. Semantic record maxima 10 links,2 addresses,3 IPv4 routes,1 IPv6 route,3 IPv4 rules,2 IPv6 rules; no truncation to maxima. Proc view <=65536 bytes each, sysfs <=11 entries, names ASCII <=15 bytes, no NUL/slash/control; all ints exact int, never bool. Namespace device/inode positive u64. Constant error `invalid B3 network profile`, no offending name/address/payload/exception chaining.

## 5. Canonical security and telemetry

Independently reviewed policy literals and exact required sets belong in future source. Compute profile_sha256 as SHA256 of domain bytes `B3-N3-POLICY-v1\0` followed by ASCII canonical JSON of policy schema1: sorted object keys,separators comma/colon,ensure_ascii=True, no floats, includes every constant/field rule/telemetry path/bound/kernel restriction; no expected_snapshot parameter and no runtime fixture loader. Future runtime policy digest is intentionally not fabricated from this prose or capture. Before implementation Root freezes the literal policy JSON bytes/hash translated from this contract, then source-review verifies source implements exactly those bytes. The separate design file digest freezes review input only and is not the runtime policy digest. Candidate capture digest is never profile digest.

security_sha256 is SHA256 of domain bytes `B3-N3-SECURITY-v1\0` followed by canonical_security_json using the same canonical JSON encoding. Security canonical JSON schema1 includes profile_id/hash,kernel_release,byteorder, namespace identity, complete sorted link records with typed static attrs including fullconf and any qualified permanent identity, sorted full address/route/rule records, sysfs controls, parsed proc structural facts and sentinel multiplicities. Preserve numeric flags/lengths/presence. Sort by exact name for links; full canonical tuple for others; reject duplicates BEFORE sorting. Namespace identity remains security material within the same actual worker, not a global constant.

Only documented counter/time values listed above leave security equality; their attribute IDs,flags,lengths and fixed nonvolatile components remain. Exclude netlink receiver pid/sequence and capture time from security comparison but retain exact original-slot and transport binding outside it. Raw observation hash is SHA256 of domain bytes `B3-N3-RAW-v1\0` followed by each component prefixed by its u64 little-endian byte length: canonical metadata JSON (release,byteorder,namespace before/after and six slot selectors/seq/pid), each raw datagram in slot/packet order, ten proc byte strings in before/after order and dev,addresses6,route4,route6,fib_trie order, then canonical raw sysfs-before JSON and sysfs-after JSON. Metadata also includes packet-count per slot so component boundaries are unambiguous. Include all counters; telemetry JSON records excluded values and origin metadata. Hash every raw byte rather than exposing it in errors/logs. N4 collects a full new six-dump observation on EACH side of installed-provenance hashing and compares security hashes within original deadline; current fixture has one set of dumps between two sysfs/proc snapshots, so it tests pure data consistency only, not two full N4 passes or atomicity. Neither two passes nor equal hashes imply an atomic snapshot.
