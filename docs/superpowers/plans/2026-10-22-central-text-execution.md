# S3-A central text execution implementation plan

> Execution approval: the user requested the next development stage on 2026-10-22. This is the first deliverable inside the approved S3 scope; media/provider production acceptance remains subsequent work.

## Outcome and global constraints

Easel keeps custom providers and legacy v1 subscription sessions. An explicitly selected central v2 subscription can run the local Codex text/function/custom/namespace tool loop through a scoped central gateway. Trusted terminal token usage settles the existing shared wallet once. Unknown dispatched cost remains held for reconciliation. The initial preview uses an isolated local fixture provider and test points; it is not live model or merchant acceptance.

- Stay on `codex/ui-redesign`; no commits, pushes, merges, resets, environment replacement, Logto changes, or unrelated process/container changes. The 198 existing dirty files are preserved. Source baseline: `/private/tmp/easel-s3-before`; state receipt: `/private/tmp/easel-s3-baseline.json`.
- Keep existing migrations 001–005 immutable. Add 006 execution tables and explicit runtime privileges; the runtime cannot publish rates/models or rewrite immutable financial history.
- Central credentials never enter browser payloads, prompts, ordinary logs, native argv, workspace archives, or native child environments. The child receives only a per-run loopback proxy token. Provider credentials remain in a private server file. No real provider key is read/reused/configured in this stage.
- Complete Scope is user/product/tenant/billing account/session/authorization epoch. New admission/dispatch checks current session and same-funding-mode membership/feature. Settlement of already incurred cost uses frozen server-owned scope, even after session revocation. Lock order: session for admission, then canonical wallet, invocation/job, reservation, lots. No network call while a SQL transaction is held.
- All amounts are bounded integer microcredits, 1,000,000 per point. Input/output rational costs are summed and rounded up once. Published model/rate definitions are immutable, accepted jobs freeze them, and no client supplied price, balance, provider URL, or actual usage is trusted.
- Explicit operation Idempotency-Key is mandatory. A repeated key/body returns the same operation; a changed body conflicts. Two legitimate identical requests with different keys charge separately. One dispatched operation has at most one physical provider attempt. After dispatch, timeout/disconnect/cancel/invalid or missing terminal usage is pending reconciliation, never a fabricated zero charge or automatic resend.
- Test and live credits/catalogs never cross. Disabled is the default. Only configured test catalog is marked test execution; live readiness requires explicit live configuration and verified model definitions. Images/video/music/ASR/TTS/voice/cloud execution remain visibly unavailable and cannot fall back to custom keys in central mode.
- Native 0.146.0 protocol evidence: `/private/tmp/easel-s3-native-protocol.md`. Set both `request_max_retries=0` and `stream_max_retries=0`; native thread/turn headers and body hashes cannot identify individual model operations. An owned local proxy allocates a fresh UUID for every accepted native POST and durably records UUID/body hash before central send. Its retries/status lookup reuse that UUID. No native app-server survives the proxy lifecycle.
- Verify with real isolated PostgreSQL, fixture HTTP/SSE and native binary, legacy/custom regression, frontend build/lint/tests and browser desktop/mobile. Back up both preview DBs before applying a migration; restart only owned central/Easel processes and preserve Logto and user state. Clearly label simulated versus live evidence.

## Shared service and product interfaces

`execution/core.py` exports `ExecutionService(db, identity)` with these async interfaces (plain dictionaries, PlatformError failures):

- `publish(definition, operator_id)` and `set_enabled(model_id, enabled, operator_id)` are operator-only, never HTTP. Definition contains id/name/version, capability=`text`, feature, products, test_only, provider_id/provider_version, verification=`fixture|live`, verification_ref, rate `{version,input:{numerator,denominator},output:{numerator,denominator}}`, limits `{max_input_bytes,max_input_tokens,max_output_tokens}`. Monetary fields in published API are decimal strings. Test fixture rates are 100/input token and 200/output token microcredits, limits 1MiB/65,536/4,096. No invented live rates.
- `catalog(scope, *, mode, bindings)` returns `{models:[safe definition views]}`; bindings is model-id→`{provider_id,provider_version,binding_hash}`. Public views include id/name/capability/rate/limits/test_only/readiness and never private endpoint/keys. Only matching active same-mode verified bindings are executable.
- `mint(scope, *, model, invocation_key, mode, bindings)` returns private `{task_token,expires_at,invocation_id,model,funding_mode,scope,base_url_path:'/v2'}`. Hash opaque token at rest. Invocation max 32 operations, cumulative spent+held ≤100,000,000 microcredits; token TTL300s and invocation TTL1800s, capped by live session/membership. Mint renewal cannot reset caps. Model/invocation-key replay conflicts if changed.
- `authenticate_task(token)` returns private context `{scope,invocation_id,model,funding_mode}`; product access tokens cannot act as task tokens or vice versa.
- `admit(context, *, key, body_hash, output_limit, bindings)` atomically reserves the conservative configured input token ceiling plus requested bounded output limit, freezes model/rate/provider binding, and creates a job. Returns job dict including id/status/attempt_id/reservation_id/model_definition/binding_hash plus `replay` metadata where available. Existing key checks occur before mutable catalog/rate checks. No current client input-token estimate.
- `dispatch(job_id, attempt_id)` revalidates live authorization and commits dispatch marker before I/O. `heartbeat(job_id,attempt_id)` extends lease. `pending(job_id,attempt_id,reason)` preserves hold. `finish(job_id,attempt_id, *, input_tokens,output_tokens,terminal_status,provider_response_id,evidence_hash,payload,content_type)` validates receipt and atomically settles + stores bounded result. Trusted internal calls only. `recover()` releases expired conclusively undispatched jobs and marks dispatched expired jobs pending; never resends. `cancel(scope,job_id)` releases only predispatch; otherwise pending. `list(scope)`/`get(scope,job_id)` scoped to current user/product/wallet. `result(context,key)` returns bounded settled cached payload or explicit running/pending/expired failure. Replays never call a provider.
- Trusted finish can settle pending with the original attempt after revocation. Over-budget usage stays pending and disables further admission for the offending binding. Replay payload max8MiB, JSON max2MiB, SSE event max256KiB, expiration24h; retain financial metadata, clear payload only via explicit retention function, never remove financial history. Store body hashes rather than prompts.

`execution_runtime.py` exports `ExecutionRuntime(db, identity, settings)` with `.service`, `.settings`, `.bindings`, async `.catalog(scope)`, `.mint(scope,data)`, `.respond(task_token,key,body)` returning Starlette response, `.capabilities(product_id)`, `.run_forever()`, `.close()`. Config class `ExecutionSettings.from_env(central_settings)` lives in `execution_config.py`; mode disabled/test/live, `CENTRAL_EXECUTION_CONFIG_FILE` server-only0600 file. Runtime owns one HTTPX async pool and bounded semaphore. Config provider fixed endpoint, secret, provider/version and public-model→upstream-model map; no redirects/env proxies, test HTTP only literal loopback, live HTTPS. Tests inject fixture settings/transport; do not reuse OpenAI env keys.

HTTP: GET `/v2/products/{product_id}/models` with product bearer; POST `/v2/task-tokens` with product bearer and `{model,invocation_key}`; POST `/v2/responses` with task bearer + Idempotency-Key; GET `/v2/executions`, GET `/v2/executions/{id}`, POST `/v2/executions/{id}/cancel`. Only responses has1MiB body bound; other routes retain64KiB. No public settlement endpoint. Capabilities expose separate test/live execution flags and pending media.

Native `subscription_backend` values `legacy|central`; missing old value means legacy. New explicit central choice is persisted. CentralClient gains safe catalog/execution GETs and private mint (not generic browser forwarding). TaskContext/RunRequest/session binding freeze backend, logical platform origin and account/scope; prior chats never silently rebind. Proxy URL/key are transient runtime values, not logical platform identity. Central account identity includes origin/user/tenant/wallet. Supported media helpers reject central text-only before dotenv loading or subprocess dispatch.
