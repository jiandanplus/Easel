# Easel 双服务模式与双执行位置交付路线图

日期：2026-10-15

依据：[总体设计](../specs/2026-10-15-subscription-and-execution-design.md)。

这是跨子项目路线图，不是已完成的开发清单，也不代替各阶段的代码实施计划。用户已确认订阅／自定义与本机／云端两组能力；本次先固定边界与阶段验收。

## 全局约束

- 模型服务来源为 custom／subscription；执行位置为 local／cloud；执行引擎保留现有适配层。
- 所有运行中的任务和现有原生会话保持创建时归属，不在切换设置时迁移。
- 自定义本机使用无需平台账号；平台模型和云端执行要求平台鉴权。
- 所有套餐能力以实际后端、权益与兼容性验证为准，不做假余额和假开通。
- 不在客户端内置上游平台总凭证，不静默切换付费来源。
- 前序交付可用后再开放依赖它的入口；每个阶段独立开发、验证和提交。

## 阶段一：边界契约与引擎验证

**产出：** 来源、执行位置、能力和任务归属的子项目设计；默认内置引擎的真实兼容性结果。

**接入点：** `easel/harnesses/base.py`、`store.py`、`commands.py`、`models.py`、`web/app.py` 的设置和任务入口，以及 `SettingsPanel.tsx`、`HarnessSettings.tsx`。

- [ ] 列出当前引擎读取凭证、模型列表、启动命令和原生会话的路径，明确统一来源解析与任务调度入口。
- [ ] 为来源、执行位置、引擎、能力和会话绑定建立互相独立的契约，规定旧配置迁移：未配置新字段时保持现有自定义本机行为。
- [ ] 验证候选默认引擎对网关认证、模型协议、工具调用、流式事件、权限与取消的支持。
- [ ] 以测试服务验证协议结构，以可用测试模型取得一次真实工具任务结果；两类证据分别记录。
- [ ] 依据兼容性结果选择默认内置引擎，记录固定版本、必要资源和分发要求。

**验收：** 有完整的配置迁移与任务归属设计；真实结果证明选定引擎能使用目标类型的服务。没有真实模型访问时，只能报告协议验证，不能报告引擎兼容性完成。

**回退：** 不改变已有引擎、凭证和会话，继续使用原自定义本机入口。

## 阶段二：内置运行时与自定义本机闭环

**产出：** 首个可下载的试验发行包，用户无需单独安装引擎即可完成任务。

**接入点：** 统一命令解析、新运行时清单、安装与启动入口、模型来源设置、任务工作区；新增打包目录与发行验证脚本。

- [ ] 根据阶段一契约实现来源设置与迁移，分别保留订阅和自定义配置；订阅后端未接通时清晰显示不可用状态。
- [ ] 包内引擎与显式外部引擎共用解析结果，安装检测、模型查询和任务启动一致。
- [ ] 准备后端运行环境、前端构建、技能和必要工具，拆分只读程序资源与可写用户数据。
- [ ] 实现启动、关闭、错误说明和版本清单；缺少能力时明确指出实际依赖。
- [ ] 在干净环境中完成自定义模型配置、真实技能调用、产物生成与升级后数据保留。

**验收：** 第一目标平台上，无 Python／Node.js／Agent CLI 的设备能够启动发行包，使用自己的兼容模型完成真实任务。其余平台分别验证，不能用本机开发环境结果代替。

**回退：** 保留源码启动方式和外部引擎选项，不修改旧用户数据。

## 阶段三：账号、模型网关、权益与账本

**产出：** 平台测试账号登录后，不填写供应商 Key 即可使用真实授权模型；服务端可核对用量。

**新服务职责：** 身份与会话、模型目录与网关、权益、用量账本。云端服务单独部署，不直接复用面向本机工作区的无隔离命令执行入口。

- [ ] 完成账号流程、访问凭证生命周期、设备撤销与客户端账号入口。
- [ ] 实现服务端模型目录、授权与网关；把用户凭证转换为有限范围调用权限。
- [ ] 实现预占、核销、释放、并发预算和幂等请求，保留规则版本与可核对记录。
- [ ] 接通内置引擎的订阅来源，验证多次工具循环、流式中断、取消和凭证刷新。
- [ ] 展示真实套餐权益与用量；模拟未登录、额度不足、服务故障和权限变化，确认不静默切换来源。

**验收：** 登录、任务、工具、用量形成真实闭环；越权模型调用、重复请求与并发超额由服务端控制。测试权益必须标注测试用途，不能宣称完成付费订阅。

**回退：** 暂停新的订阅任务，保留自定义模式；完成或停止已有任务后再切换，不丢失账本。

## 阶段四：订单与付费订阅

**产出：** 可验证的下单、支付确认、开通、续期与到期闭环。

**阶段输入：** 面向的销售区域、支付渠道、套餐权益与金额、退款和自动续费规则。由对应子项目设计记录具体选择后实现，不凭总体方向推定商业条款。

- [ ] 建立订单、订阅、支付事件与权益变更的数据关系及幂等键。
- [ ] 在支付沙箱实现服务端验签与状态核验，保证重放、乱序和超时重试可恢复。
- [ ] 接通客户端订阅管理和用量入口，区分订单已支付、权益已生效、待核验和失败状态。
- [ ] 验证到期、取消续费和已运行任务的预算边界，规则进入产品文案与任务快照。

**验收：** 沙箱支付、重复回调、到期和异常恢复有可核对记录。正式收款单独执行上线步骤；沙箱验证不代表已经开通正式支付。

**回退：** 停止创建新订单，保留订单核验和已支付权益查询，不删除支付记录。

## 阶段五：云端任务

**产出：** 用户按任务选择本机或云端，云端任务可脱离客户端持续运行。

**新服务职责：** 任务 API、持久化队列、调度器、隔离执行环境、文件与产物存储、持久化事件。

- [ ] 实现统一任务描述、所有权、幂等提交和状态机，保留来源、引擎、执行位置及预算快照。
- [ ] 实现云端工作区准备与素材选择上传，拒绝云端不可达的本机 localhost 模型与不支持的本机专属能力。
- [ ] 复用引擎适配器运行任务，提供任务范围凭证与受限环境，验证用户／任务文件隔离。
- [ ] 实现事件游标、授权等待、重连、取消确认、执行器失联核对和产物下载。
- [ ] 分开记录模型、执行与存储消耗，验证自定义云端任务的模型凭证清理与资源计量。

**验收：** 关闭客户端后任务继续；重连恢复进度；审批等待和取消有效；重复提交不重复执行；任务之间不可读取对方文件与凭证；下载得到实际产物。

**回退：** 暂停接收新云端任务，保留已有任务的查询、取消和产物下载，本机任务继续使用原执行位置。

## 阶段六：媒体通道与多平台发布

**产出：** 按真实支持范围开放转录、配音、生图、视频和音乐；发布各平台通过验证的发行包。

- [ ] 为每个通道单独规定调用契约、计量单位、可取消边界和产物验证方式。
- [ ] 修改对应技能的服务解析，验证它们确实使用所选来源与额度，不遗漏独立脚本中的第三方接口。
- [ ] 对声明支持的每个通道生成真实产物并核对用量，失败和部分完成按实际消耗结算。
- [ ] 对各操作系统／架构完成无开发环境的发行验收、升级保留数据、卸载与运行时版本验证。

**验收：** 每个公开可选项有真实能力与产物证据；发行矩阵逐项记录结果，不将一个平台的通过推广为全平台完成。
