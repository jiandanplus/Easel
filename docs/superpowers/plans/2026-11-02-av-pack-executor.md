## Root clarification: namespace-relative cgroup root (2026-11-02)

Linux kernel cgroupv2 namespace documentation shows that a process in a private cgroup namespace commonly sees `0::/`; this is its namespace root, not proof it shares the host root. Worker validates actual self path and cgroup2 mount root/readonly visibility, finite exact memory/swap/PID/CPU controls and available self/parent namespace identity. Do not invent or require a Docker CID path hidden by a private namespace. Exact host `CgroupnsMode=private` admission/inspection is an additional Task2 requirement; a worker-only root path cannot independently distinguish a host namespace, and report must retain this evidence boundary. Add valid private-root synthetic view and reject missing/unlimited/mismatchedmount facts. This changes no resource limit or oldremoteROOTgate.

Primary sources: [Linux cgroupv2 namespace Basics](https://www.kernel.org/doc/html/v6.14/admin-guide/cgroup-v2.html), [Docker cgroupv2 runtime metrics](https://docs.docker.com/engine/containers/runmetrics/). Root browsed exact official primary text after agent raised a valid compatibility question; no actual preflight performed.
