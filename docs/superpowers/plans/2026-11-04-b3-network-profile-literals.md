## 1. Policy correspondence and closed semantics

The literal is schema 1 with mandatory `NoUnknownKeys=true`. Every object in the policy must exactly equal the corresponding object in its constant schema. Unknown keys, optional additions and absent keys are prohibited. All required attribute descriptors use exactly `id`, `flags`, `length`, `rule`. Attribute IDs are the low 14 bits; flags are the separate high bits. `length` counts payload bytes, excluding the four-byte NLA header. Nested lengths include aligned child TLVs, including their padding. Padding remains N1's validity responsibility; serialization does not repair it.

- Frozen contract §1 maps to `profile_id`, `kernel_release`, `byteorder`, `slots`, `bounds`, `requirements`, `error`. Six exact slot triples are request type/family/sequence. Same positive u32 local port ID across all six remains an observation-dependent constraint. Namespace device/inode are positive u64 and must match before/after; they are never policy constants. All provided integer fields require exact integer runtime types, excluding bool and subclasses. Input dataclasses must have exact declared types, tuples and bytes, with no callbacks or configurable policy. Generic errors must be exactly the frozen string, without offending content or chained exceptions. Original datagrams must be reparsed by N1 and message equality checked, irrespective of cached parsed data.
- §2 maps to ten fully expanded `links`: complete headers, separate index ranges, complete sysfs facts, and every required attribute. Each set is closed and each ID must occur exactly once. lo index is 1; each fallback index is unique and in 2..2147483647. Link names/indexes are globally unique. Every address/end-point zero and broadcast exception is explicit hex. All nested linkinfo, AF_SPEC, XDP and empty flagged nests are fully expanded. `configuration_vectors` redundantly spells out all 33/59 values as unsigned decimal bit patterns for review; the vectors MUST equal the corresponding fixed hex payloads and introduce no variability. Attribute 54 is present only for its three named IPv6 fallback links.
- §3 maps to `addresses`, `routes`, `rules`: exact header key sets and exact required attribute sets. They are complete multisets, not partial templates. Missing/extra/duplicate records reject. A rule with absent priority cannot substitute an explicit zero priority. No netlink null/default route is authorized by proc sentinels.
- §4 maps to `sysfs_controls`, `proc_security`, `proc_lexical` and the cross-view requirements. Exactly one root-owned regular bonding_masters file, mode decimal 420 (0644), is required, with the ten interface entries. Controls cannot stand in for interfaces. Control file type in the reference fixture adapter is derived from its declared kind solely for serialization; it is not actual filesystem provenance. Proc use remains fixed zero on all three rows; only refcount varies. Both trie sections, all structural node fields and leaf order are preserved. No new table IDs are inferred.
- §5 maps to `encoding`, `schemas`, `ordering`, `telemetry_paths`, `raw_framing`, and the following exact serialization rules. §6 remains a future source TDD/review gate, not a claim about this data task.

Closed rule grammar (also in `rule_grammar`): `fixed` has exactly tag/hex and compares all payload bytes. `children` has exactly tag/attributes and recursively requires the exact child set. `words` has exactly tag/bits/values; bits is 32 or 64, length is values count times bits/8, little-endian unsigned; each literal integer must match that exact word and each null admits any unsigned word of that width. `permanent_identity` has exactly tag/first_byte_mask/first_byte_value/zero_suffix_offset/zero_suffix_length, with constants 3/2/6/10; payload length is 16. Full observed permanent identity bytes survive security serialization. There are no other rule tags or wildcard/opaque rules. Values are never signed JSON integers; 0xffffffff is 4294967295.

The scope of null words is exact: link stats 24 u32 and 25 u64; three individual carrier u32; AF10 statistics after fixed count words 38/7; AF10 cache words 1/2, while words 0/3 are 65535/1000; address cache timestamp words 2/3, while lifetime words 0/1 are 0xffffffff. Full AF configuration, permanent address, route cache and proc use are static. `telemetry_paths` names the parent attribute paths; `words.values` fixes the exact volatile positions. No other field can be excluded.

## 2. Closed serialization schemas

`security.schema.json`, `metadata.schema.json`, `rawsysfs.schema.json`, `telemetry.schema.json` are JSON Schema 2020-12 shape documents with all object members required and `additionalProperties=false`. They share the exact `$defs` embedded in policy. Their shape constraints and the stricter policy values/relationships are BOTH mandatory; shape alone is never profile acceptance. No `$ref` leaves its own document. The schema URI is descriptive and requires no network access. JSON Schema's mathematical integer type is supplemented by the exact runtime-int requirement above.

Every byte string is lowercase even-length hex (two characters per byte). Empty bytes are the empty string. A `hex` attribute's string length MUST be twice its payload length. A `words` attribute's length MUST equal its array count times bits/8, each non-null value must fit its declared width, and null positions MUST be precisely those in its source rule. A `children` attribute's payload length MUST equal the sum of aligned child TLV lengths. Static leaves are represented as hex, including full configuration vectors and permanent identities; numeric headers retain explicit unsigned integer fields. Exact payload interpretation is supplied by policy, not by dynamic type inference.

Security top-level keys are exactly schema/profile_id/profile_sha256/kernel_release/byteorder/namespace/links/addresses/routes/rules/sysfs_controls/proc. The profile hash is 64 lowercase hex characters and must equal the source-owned policy digest. Each link is exactly name/header/attributes; each address, route and rule is exactly header/attributes. Header keys are all spelled out in the schema; none are optional. Each attribute is exactly id/flags/length/value. Value is one of `{tag:"hex",hex:...}`, `{tag:"children",attributes:[...]}`, `{tag:"words",bits:32|64,values:[...]}`. No original volatile word is left inside canonical security. Counters' presence, lengths, flags, widths, slot counts and fixed header words remain.

Reject duplicates and unknown fields before canonicalization; never use last-wins maps to erase them. Attributes sort recursively by integer ID at every parent. Links sort by ASCII name. Addresses/routes/rules sort lexicographically by the ASCII canonical JSON bytes of the COMPLETE canonical record (sorted object keys, so the attributes member precedes header). This is the exact full-record tuple/order definition; sorting headers alone is insufficient. Duplicate full static records reject before sorting and all exact inventories still apply. Sysfs controls sort by name. Proc dev security entries sort by name. Address6 entries and grouped route6 facts sort by complete canonical JSON bytes. Trie sections remain Main then Local, with literal node and leaf sequence.

Proc route6 aggregates only identical static facts. The two reject/null sentinel rows become one fact with `multiplicity:2,table_id:null`; the ::1 row has multiplicity 1 and table_id null. Each source row is checked individually, including use=0, before grouping. Exactly two sentinels are allowed, never deduplicated to multiplicity 1. Refcounts retain original row ordinals in telemetry. The policy's exact `proc_security` constant includes all static proc structure and dev counter placeholder lengths. Before/after parsed static proc/sysfs views and reparsed netlink must agree BEFORE selecting the single canonical security view. In particular before/after namespace and each permanent identity within separate complete passes must not be normalized away.

Raw metadata has exactly schema/kernel_release/byteorder/namespace_before/namespace_after/slots. Slot objects have exactly request_type/family/sequence/local_portid/packet_count in ORIGINAL six-slot order. Raw sysfs has exactly schema/entries and preserves original tuple order. Interface entries have tag/name/index/iflink/arphrd/flags/operstate/address_hex; control entries have tag/name/uid/gid/mode/file_type. Every raw observation field survives either metadata, datagrams, original proc bytes, or these sysfs objects. There is no optional component and no capture timestamp in the frozen NetworkObservation data model. Transport sequence/port ID are outside security but inside metadata/raw hashing, and still must be independently validated.

Telemetry has exactly schema/origin/netlink/proc_before/proc_after. Origin is the complete raw metadata object. Each netlink telemetry entry has slot (zero-based), record (zero-based semantic record ordinal within that slot, excluding DONE), path (nested numeric attribute IDs), bits, values. Traverse original slot/packet/message order and depth-first original attribute order; emit exactly one entry for every words-rule attribute, including its fixed header words, with ALL actual unsigned words. The values array is never reordered or truncated. Proc telemetry dev entries retain original row order and all 16 u64 counters; route6 entries retain row ordinal and unsigned32 reference_count for each of the original three rows. Proc use is retained in canonical security, not reported as variable telemetry. Raw preserves all exact bytes and textual ordering.

No acceptance normalization is added: canonical sorting happens only after original shape/duplicate/padding/static/consistency checks. Numeric/byte re-encoding is solely the output representation. Names remain the exact ten ASCII names. Root confirmed the precise lexical rules below; structural and numeric requirements are fixed.

## 3. Exact bytes and hashing

All JSON artifact filenames ending `.canonical.json` contain ASCII bytes with `sort_keys=True`, separators comma and colon, `ensure_ascii=True`, no floats/NaN/infinity, no decoded NUL characters in JSON string values, and NO trailing newline/BOM. Hex payloads may of course represent zero bytes. Booleans exist only for explicitly boolean policy/schema fields, never integers. Canonical JSON schema tags are integer 1, not strings.

Domain separators are the ASCII prefix followed by exactly ONE zero byte:

- Policy: `B3-N3-POLICY-v1` + 00; hex `42332d4e332d504f4c4943592d763100`.
- Security: `B3-N3-SECURITY-v1` + 00; hex `42332d4e332d53454355524954592d763100`.
- Raw: `B3-N3-RAW-v1` + 00; hex `42332d4e332d5241572d763100`.

profile_sha256 = SHA256(policy domain || policy canonical bytes). security_sha256 = SHA256(security domain || canonical security bytes). No JSON string-encoded separator, backslash-zero, repeated NUL, newline or length prefix occurs in those two constructions. `policy.digest.json` records the canonical file SHA separately from the domain-separated profile SHA. Design/fixture digests are review/provenance references, never the runtime profile hash.

Raw = SHA256(raw domain || concatenated frames). Each frame is u64 LITTLE-ENDIAN byte length immediately followed by precisely those bytes. Frame order: canonical metadata; every datagram in original slot/packet order; before dev/addresses6/route4/route6/fib_trie; after those same five fields; canonical raw sysfs-before; canonical raw sysfs-after. Metadata packet counts disambiguate the variable number of datagram frames. Each required zero-length component, if representable, contributes eight zero bytes; it is not omitted. There are no null/optional components, packet lists of length zero have zero datagram frames and explicit packet_count=0 but still must satisfy original N1/profile dump semantics. Raw-domain bytes appear once, outside frames. `fixture.raw.framed.bin` contains the COMPLETE preimage including domain and every frame; its ordinary SHA256 is raw_observation_sha256.
