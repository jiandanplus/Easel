# 0013 兑换码和网页审批后台账号（迁移 026）

日期：2026-11-07 · 状态：已实施，用户选择“开始第三批”

## 背景
付款还没开放，给朋友或测试用户发额度只能逐个在后台操作，而且需要知道对方的钱包。新同事要用后台，也只能由运营者在服务器上运行命令批准。

## 决定
**兑换码**
- 只有 `admin` 能生成：选一个已发布的套餐（和 0012 一样，最多 100 点、365 天，内部体验额度和所有者额度除外），一次生成 1 到 100 个码，并设定 1 到 365 天的有效期。
- 码有 16 位，字符取自 Crockford base32（去掉容易看错的 I、L、O、U），约 80 位随机性。数据库只保存 SHA-256 摘要；明文只在生成后的那次响应里显示一次，连用于重放的操作记录里也不保存。
- 用户登录桌面版后，在“账号与订阅”里输入兑换码。产品运行时调用唯一允许它调用的函数 `redeem_code`：每个码只能用一次；同一个钱包在一个批次里只能兑换一个；已停用或已过期的批次不能兑换；同一个人重复提交同一个码，返回第一次的结果，不会重复加点。
- 发放的会员资格、额度批次和发放分录在提交时由数据库核对。批次只能停用，不能修改或删除；码只能从“未使用”变为“已兑换”。
- Console 角色不能调用 `redeem_code`，runtime 也不能调用任何 Console 函数，双方的启动检查都会拒绝越权。

**网页审批后台账号**
- `admin` 可以在“后台账号”页批准登录申请，但只能批准为 `operator` 或 `viewer`；批准 `admin` 仍需在服务器上操作。
- `admin` 可以停用 `operator` 和 `viewer`，不能停用自己，也不能停用其他 `admin`。
- 每次批准和停用都写入不可修改的 `console_acl_events`，操作人记为 `console:<管理员编号>`。

## 影响
- 拿到管理员会话的人，可以按已发布、不超过 100 点的套餐批量生成兑换码；每个钱包每个批次最多领取一次。点数不是付款，真实费用仍由供应商收取。
- 兑换入口在桌面版 v47 及以后的版本里。
