# 0012 运营后台管理用户：停用、强制下线、备注、按套餐发放（迁移 025）

日期：2026-11-07 · 状态：已实施，用户选择“开始第二批”

## 背景
第一批让后台看得清。New API 后台还能封禁用户、调整额度；优创后台只能看，出了问题仍要用服务器命令。

## 决定
- **停用或启用账号**（`admin`、`operator`）：停用会把账号设为不可用，同时提升登录版本号，用户的所有登录立即失效，也无法再登录。余额和记录都保留，可以重新启用；重新启用后需要本人重新登录。
- **强制下线**（`admin`、`operator`）：提升登录版本号，并把未过期的登录标记为已退出，账号本身不受影响。
- **备注和标签**（`admin`、`operator`）：写在 Console 自己的表 `console_user_notes` 里，产品从不读取。备注最多 500 字，标签最多 10 个、每个不超过 20 个字，可以按标签和备注搜索。
- **按套餐发放**（只限 `admin`）：从已发布的套餐里选一个发给钱包。上限是 100 点、365 天；内部体验和所有者额度这两个套餐走各自的路径，这里不能发。同一钱包的同一套餐，在上一次 Console 发放到期前不能再发。每次发放都写入不可修改的 `console_plan_grants`，数据库在提交时核对会员、额度批次和发放分录。
- 和 0011 一样，Console 数据库角色仍然不能直接改用户或账本：停用、下线和发放都只能调用 `SECURITY DEFINER` 函数，函数内部会再次核对调用者的角色，runtime 和 PUBLIC 都不能调用，runtime 启动检查会拒绝。每次操作都要填写原因，带幂等键，并留下审计记录。

## 不做
- **删除用户**：账目要保留，用停用代替。
- **直接改余额、自定义发放数量**：只能按已发布的套餐发放。

## 影响
- 发放点数的权限从“固定 100 点”扩大到“任意不超过 100 点、365 天的已发布套餐”。拿到管理员会话的人，最多能给每个钱包、每个这类套餐发一次，到期后才能再发。点数不是付款，真实费用仍由供应商收取。
