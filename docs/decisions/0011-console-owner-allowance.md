# 0011 运营后台显示用户名和邮箱、网页发放所有者额度（迁移 023、024）

日期：2026-11-07 · 状态：已实施，用户要求“继续完成没有完成优化的部分”（运营后台第二、三期）

## 背景
第一期后台只显示用户编号，认不出是谁。所有者额度（[决策 0010](0010-owner-allowance.md)）只能由主机命令发放，用户自己不会用命令行。

## 决定
**第二期：认人。**
- 迁移 023 给 `external_identities` 加 `username`。产品登录时从签名的 ID Token 记下 `username`，格式不对就丢弃，不影响登录；它只用于显示，从不参与授权。已有账号要等本人下次登录后才有用户名。
- 后台用户列表和详情显示用户名、邮箱，搜索也能按用户名和邮箱查。issuer、subject 仍然不给 Console。

**第三期：网页发放所有者额度。**
- 只发 0010 的固定套餐：100 点、365 天、文本和图片。网页和接口都不能指定数量或时长。
- 只有 `admin` 角色有 `owner:allowance`；`operator`、`viewer` 没有。
- Console 数据库角色仍然不能直接写账本。迁移 024 新增一个 `SECURITY DEFINER` 函数 `console_issue_owner_allowance`，只有 Console 角色能执行（runtime 和 PUBLIC 都不能，runtime 启动检查会拒绝）。函数内部会再次确认调用者是启用中的 `admin`，把账本和 0022 的一致性检查放在函数里立即执行，`search_path` 固定为本 schema 加 `pg_temp`。
- 每次发放都要填原因，带幂等键；业务结果、操作记录和审计在同一事务提交。发放记录写入 `owner_grants`，`operator_id` 为 `console:<管理员编号>`，批准依据记为 `console-web`，不可修改、不可删除。
- 同一钱包的所有者额度到期前不能再发，这条规则仍由数据库保证。

## 影响
- 这改动了 CONSOLE.md 原先“网页不能发点”的规则，但只放开这一种固定额度。测试发点、内部体验发放、自定义数量、退款和手工付款确认仍然没有网页入口。
- 风险上限：拿到管理员会话的人，最多给每个钱包每 365 天发一次 100 点。点数不是付款，真实费用仍由供应商收取。
- 主机命令 `owner-grant` 保留不变。
