# 0020 后台管理用户：新建、编辑、删除、角色、余额和套餐

日期：2026-11-10 · 状态：已实现，待上线

## 背景
用户页原来只能查看、停用、强制下线、写备注和按套餐发放（上限 100 点，现有套餐 1000–10000 点，一个都发不了）。运营需要在后台直接新建和管理账号、设置管理员、调整余额和更换套餐。

## 决定
- **角色只有管理员和用户两种可选。** 管理员就是能登录这个后台的 `admin`，按本人的登录身份（Logto 用户编号）直接授权，不再要求先在后台登录提交申请。只有管理员能改角色；不能取消自己，也不能取消最后一个管理员。原来的运营者、只读查看者照旧显示和使用。这推翻了决策 0013 里“批准管理员仍需用服务器命令”。
- **删除是软删除。** 删除后立即退出所有设备、不能登录，Logto 里同时禁止登录；用户列表默认不显示，在“已删除”筛选里能找到。余额、套餐和所有记录都保留，可以恢复。管理员要先改成用户才能删除。不做硬删除，因为账目和审计必须保留。
- **新建、编辑资料、重置密码走 Logto Management API。** 后台用一个只给后台用的机器对机器应用（默认租户，Management API 角色），凭据只在后台服务的环境文件里。新建的账号立刻在中央建好用户和钱包，登录前就能发套餐。密码只转交 Logto 一次，不记录、不写日志、不进审计摘要。没配置时这些按钮置灰。
- **加点挂在用户当前的正式套餐上**（新建一个同套餐、同到期时间的批次），跟套餐一起到期，能用的功能和模型也一样，不会因为加点而解锁套餐外的东西。没有生效套餐时拒绝，先发套餐。**扣点**从最早到期的正式点数扣起，不能扣成负数。账本新增分录类型 `adjust`：扣减把点数从“可用”移到“已过期”，每个批次依旧守恒。每次增减记入 `console_credit_adjustments`，不可修改。单次最多 100 万点。
- **更换套餐 = 发放新套餐 + 结束旧套餐。** 结束套餐写入 `membership_revocations`（现在可以来自订单，也可以来自后台操作员），这个套餐给的功能立即失效，剩余点数作废（同样记为 `adjust`）。有进行中的调用时不能结束。后台按套餐发放的上限从 100 点提高到 100 万点，天数上限仍为 365 天。
- 以上每个操作都要填原因、带幂等键，结果和审计在同一事务提交；所有写入都通过 SECURITY DEFINER 函数并在函数内再次检查管理员身份（迁移 038）。

## 不做
硬删除账号；绕过套餐单独卖点数包（另议）；修改已有套餐批次的到期时间。
