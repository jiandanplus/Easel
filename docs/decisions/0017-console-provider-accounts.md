# 0017：同一平台可以接入多个账号，后台改成“新建接入”

日期：2026-11-09

## 背景

决策 0016 让每一类接口可以配置多个平台，但每个平台只能存一套地址和 Key，页面也是下拉选平台再填表，一次只能看到一个。管理员希望同一类接入多家、同一家接入多个账号，并能一次看到全部。

## 决定

- 每一类接口下是一张“接入”列表，点“新建接入”增加一条，可编辑、删除。每条有自己的名称、平台、地址、Key 和检测结果。
- `provider_configs` 和 `provider_config_status` 增加 `account`（迁移 032）。空字符串是平台原有的那一条，供应商标识不变，线上已绑定的模型不受影响；新建的接入得到 8 位十六进制账号，标识是 `console-<类别>-<平台>-<账号>`，声音复刻再加 `-clone`。
- 账号由请求的幂等键算出，重试落到同一条接入，Key 也能按账号封存。Key 的封存范围包含账号，不能挪到同平台的另一条接入。
- 新建的 New API 接入只服务绑定到它的模型。只有“服务器配置”那一行点“改为后台配置”，才会接管服务器文件里的模型（行为同决策 0015）。
- 接入名称在同一类里不能重复。只有 Key 的行算现存接入，删除就是追加一条没有 Key 的记录，不改历史。还有启用中的模型时不能删除。
- 同一模型拉取到第二条接入时，显示名后面加接入名称，用户才分得清。
- 发给桌面的媒体模型最多 100 个，超过的不发。桌面收到更长的列表会整体拒绝，所有媒体工具都会消失。

## 拉取音色（迁移 033）

- Fish Audio、MiniMax、阿里 CosyVoice 的接入可以先不填音色，保存后由中央服务用它持有的 Key 查询音色列表，存到检测结果里供后台勾选。后台自己打不开 Key，所以“重新拉取”和搜索都是保存一条新记录、触发一次检测。
- 没选音色的配音接入不提供服务，也不能添加模型，但仍会去查列表。
- Fish Audio 默认列出账号自己的声音和热门中文公开声音，搜索时改为按名称查公开声音。CosyVoice 只能查到复刻音色，系统预设音色仍要手填。
- 这几家没有列出配音模型的接口，所以配音的“拉取模型”用内置在代码里的官方文档型号（Gemini TTS 同样，避免混入非配音模型）。厂商出新型号时要更新代码，或用“添加模型”手填。Fish 的 `s1` 将于 2026-12-31 退役，MiniMax 的 `speech-01-*` 官方状态不明，都没有列入。
- 音色 ID 允许空格和括号，因为 MiniMax 的系统音色带这些字符。
- 中央服务把模型可用的音色放进发给桌面的参数里，否则桌面的 AI 只能猜音色。

## 不做

一条接入失败时自动切到另一条。一次调用只走模型绑定的接入，需要自动切换时放到 New API 里做。
