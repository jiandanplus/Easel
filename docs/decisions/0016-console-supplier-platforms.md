# 0016 后台每一类接口可选第三方平台（迁移 029）

日期：2026-11-09 · 状态：已上线（2026-11-09）

## 背景
桌面端的自定义配置适配了多家第三方平台。用户要求把这些平台也迁到中央后台。决策 0015 里“每一类只有一组地址和 Key”的做法不够用，本决策取代这一条。

## 决定
**页面**
- 每一类分页增加“平台”选择，每个平台分别保存地址和 Key，互不影响。平台清单和各自的字段由服务端定义，页面照着显示。
- “gateway”平台沿用决策 0015：保存后接管这一页服务器文件里的模型。其他平台只服务绑定到它的新模型。

**迁移的平台**
| 分页 | 平台 |
|---|---|
| 对话与脚本 | OpenAI Responses / New API、OpenAI 兼容（DeepSeek、中转站）、Anthropic |
| 语音转写 | OpenAI 兼容 / New API、硅基流动 |
| 配音 | OpenAI 兼容 / New API、阿里 CosyVoice、MiniMax、Fish Audio、Gemini TTS |
| 生图 | New API 网关、OpenAI 兼容 / apimart |
| 视频 | OpenAI 兼容 / New API、通义万相、火山 Seedance、可灵、Agnes |
| 音乐 | New API 网关（Suno）、阿里 DashScope、Suno 类第三方 |

**没有迁移的**
- 小红书 MaaS：内网地址，服务器访问不到。
- 本地 / 内网 API 直连、本机 Claude Code / Gemini CLI：都依赖用户自己的电脑。
- 声音复刻：需要为每个用户保存声音，要单独做一轮。图生视频也还没有开放，后台模板只有文生视频。

**对话的转换**
- 客户端只讲 Responses 协议。Chat Completions 和 Anthropic 的回复由中央服务转换成同样的事件，结算逻辑不变。
- 没有返回 token 用量的回复不会产生完成事件，因此不会结算。
- 对话平台只支持 function 类型的工具。Codex 的 custom 工具在这些平台上会被直接拒绝，不产生调用。

**请求编号**
- 只有 OpenAI 官方会返回 `req_` 开头的编号。后台配置的接口改用本服务发出的编号（`easel_client_request_v1`）作为证据。

**结果下载**
- 通义、火山、可灵等的结果放在各自的存储上，地址里的主机名按平台后缀放行，下载时不带 Key；其他主机要填“结果下载域名”。

**接口地址以官方文档为准**
- 桌面端的部分写法已过时。通义万相 wan2.7 改用 `resolution` + `ratio`，CosyVoice 的路径是 `SpeechSynthesizer`，这里按官方文档实现。

## 影响
- 这些协议只用文档和测试夹具验证过，都没有用真实 Key 调用过。正式启用前要用试用账号逐个跑通。
- 没有模型列表的平台（通义、MiniMax、Fish、可灵、Agnes、Suno 类）保存时不能检测 Key，第一次真实调用才知道对错。Key 填错时，那次调用的点数会被挂起，要在后台人工处理。
- 回滚：029 只加字段、放宽约束。旧版代码忽略 `platform` 列，但会把非 gateway 平台的配置当作同一页的重复行，回滚前要清除这些平台的 Key。
