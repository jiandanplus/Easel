# 0006 媒体维护许可改为可选，默认关闭

日期：2026-11-06 · 状态：已实施（用户确认）

## 背景
源码中订阅媒体的每次写入（下单、产物登记、结算、清理）都要先取得 B2 维护许可。许可依赖数据库里由 B2 安装程序建立的 `easel_backup_control`、服务器控制锁与源目录；缺一项媒体写入即返回 503。生产仍是 10-27 发布（迁移 016），没有这套控制，所以图片功能现在可用；但按当前源码发布任何中央版本，已上线的图片都会变成 503。B2 已冻结（[0001](0001-freeze-b2-b3-av.md)）。

## 决定
媒体配置新增 `maintenance`：
- `"local"`（默认）：许可由进程内的 `LocalControl` 签发与校验。许可、物理引用、写入与回收凭证的类型和检查都不变；写入方归属与回收空闲由控制端回答，不需要数据库结构或锁文件。
- `"control"`：原 B2 数据库控制与跨进程写入屏障，行为不变。

媒体代码中直接访问 `easel_backup_control` 的 SQL 改为向控制端询问（`blob_writer_owned`、`gc_idle_sql`、`gc_writer_idle`），数据库控制端仍执行原 SQL。

## 影响
- 当前源码可以重新发布，已上线的图片功能不受影响；视频、音乐、语音可按计划逐个开放。
- 本地模式假设由一个中央 API 进程独占媒体根目录（与现部署一致）。
- 数据库与媒体文件分别备份，不在同一时刻；恢复后最近登记的文件可能缺失，多余文件可清理。需要严格一致的备份时改用 `"control"` 并部署 B2。
