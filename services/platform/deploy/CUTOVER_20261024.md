
如果新管理端 origin／端口改变，还要按固定版本核查 Logto 自身 Console 的回调与配置。**所有会改数据库的回调准备必须在最终身份备份之前完成并纳入备份**。恢复目标在两库比较／proof／apply 完成前不得启动 Logto、打开管理页、变更回调或执行登录；这些动作会改变会话或应用数据，使静态一致性证据失效。源 Logto 也必须停止所有写入。

在私有目录预演备份命令，维护者核对服务名实际对应的主机／库／角色。真实库／角色与安全配置的归档留在原主机受控目录，备份权限 `0600`、父目录 `0700`。中央库的演练恢复目的地是全新隔离库，默认不能消费。先完成一次真实中央与身份备份的实际隔离恢复、结构／权限与账本核对，再安排最终窗口；本批仅完成合成库恢复，尚未完成这一项。

## 4. 写入截止与旧 writer 隔离

1. 公告维护窗口，暂停新登录／注册、新任务、新购买、后台目录写操作和所有产品派发。客户端停止任务，在旧地址正常退出。记录原入口、配置与恢复步骤；保留旧入口用于退出，不能先拆桥。
2. 用可信 owner／统计角色列出全部业务 writer、连接与管理器。原 API／Console 分别验证环境 ID、PID、UID、`/proc/<pid>/stat` 启动时间、命令、CWD、父进程与启动管理器；确认没有 systemd／容器／定时任务／SSH wrapper 自动拉起。不得用 `pkill python` 或按端口误停其他产品。
3. 等待并记录在途任务最终事实，逐项处理 late completion、支付查单／通知队列和待核账。未知模型费用保持预留／pending；无可靠事实不得结零。预检看到的 7 个已结算任务只是当时状态，正式截止时重新查询。
4. 依次停止已绑定的旧 API／Console 及相关后台 writer，阻止其重启。用管理员权限验证角色准入、现存连接与后台任务都已被隔离；仅 `NOLOGIN` 不能终止已有连接，仅停派发也不能阻止结算写入。保存经审查的角色状态与恢复步骤；不盲目断开整台数据库。
5. 处理旧产品会话、handoff、登录事务与 Console 会话的迁移策略。修改 issuer 或 epoch 不会自动清理全部旧登录／事务。若采用撤销，必须使用受审操作，先记录需保留的关联与审计，不擅自直接删除行；若保留，则明确旧入口不能继续成为可消费 writer。
6. 冻结源 IdP 写入：停止源 Logto 和依赖其写入的管理／同步任务，确认数据库 owner 级视角下无其他写入来源；维护只读采集连接单独记录。不要停止同机其他产品的 PostgreSQL 或 Docker。
7. 记录最终核账截止点、pending／预留、订单、各资金桶和 journal 摘要，生成最后的中央与 IdP 备份并核对 SHA。统计权限不足而显示 `state=NULL` 不能证明连接空闲。

只有旧 writer 无法继续写账，才允许加载使用新锁协议的代码。不得混跑旧身份锁算法和新 1024 槽锁算法。正式窗口任一步无法证明隔离就停止推进，保留现状与待核账。

## 5. 恢复与身份连续性

1. 在服务器全新持久 IdP 数据库恢复最终批准的源备份，保留原 `tenant_id`、用户 `id`、应用 ID 与数据。恢复后重建已记录 owner／ACL／默认权限／角色关系；不以 `--no-owner --no-acl` 的恢复结果冒充权限一致。
2. API／Console 仍停止。中央权威库原地执行已审查的 additive migration 010，001–009 SHA 不变；更新 runtime 与 Console grants，用实际低权连接验证守卫。owner 只用于一次性命令，不进入常驻进程环境。
3. 在源与恢复 IdP 都静止时，使用私有配置运行 `identity-restore-proof`。配置内只使用显式真实 DSN、批准的归档与 SHA，覆盖上表两个应用 ID。检查全表、结构、序列、enum、RLS、函数、用户及应用，以及中央候选清单；不能提供手工 user 映射。
4. 在 freshness／proof 期限内执行 inspect。候选数量、摘要或占用有冲突即停止；候选保持后用唯一幂等 key 与原因执行 apply。成功后产品映射回原 user／tenant／wallet，Console alias 回原 admin／role／active。禁用管理员保持禁用。
5. 保存 consumed、审计和中央库前后账本证明，再备份迁移后的中央库。不得发点、搬余额、重建钱包、删除旧 issuer 或授权新管理员来让验收通过。

两库相等与 alias 应用完成是这一阶段的证据；本人新 issuer 登录仍需第 7 节独立验证。若 proof 在比较后过期，不复用旧回执，保持静止并重新采集。

## 6. 代理、TLS、配置与服务

实际观测的 `1panel-openresty` 是 80／443 的入口；执行前重新核对精确容器身份。实际配置中只有原 New API 的 `api.drawbookai.cn` 等站点，没有本次 accounts／console／login 三个站点。使用已有 1Panel／OpenResty 的受控站点流程增设，**不另外启动代理抢占 80／443**。

宿主 `/opt/1panel/www/conf.d` 挂载到 OpenResty `/usr/local/openresty/nginx/conf/conf.d`；宿主 `/opt/1panel/www` 挂载到容器 `/www`。包内 `nginx-central.conf` 是通用模板，正式安装必须核对容器视角的 upstream 可达性、证书路径及权限。宿主 loopback `19874/19875` 不等于 bridge 容器 loopback；先确认 OpenResty network mode，再审查最小可达路径，不能为连通而把数据库或服务暴露到公网。login 的双端口认证／管理路由另按固定版本配置，管理端只对受控运营网络开放。

1. 准备三域名匹配的有效证书、续期、证书权限与备份；受验证 TLS 必须通过，不用 `-k`。保留现有 New API 站点、默认站点和续期配置。
2. Logto 配置正式 `ENDPOINT`、独立 `ADMIN_ENDPOINT`、HTTPS 代理信任和持久 DB；启动前确认没有待执行的未审 schema alteration。目标启动后不再要求与静止源全表完全相同，迁移前静态证据与启动后变化分别保存。
3. 真实 API／Console env 各自属于非 root 服务用户，`0600`，不含模板 REPLACE。API 使用同一权威 schema；Console 仅低权 DSN 和自己的 OIDC secret。默认支付 disabled；模型只保留已审条目，供应商凭据只在服务器使用。
4. 核对新 unit、release 权限、systemd 指令支持情况和资源限制；仅启动新入口，旧 writer 保持隔离。未验收前代理不开放消费入口；健康探测不能触发模型或付款。
5. 在**现有** OpenResty 中配置检查通过后才受控 reload；分别验证三个规范 Host、正确证书和入口。默认站点对新域名返回内容不代表该产品可用。禁止记录授权码、Cookie、Authorization 或完整请求行。

## 8. 失败与回退

任何步骤未通过时，保持新入口关闭并保留全部备份、pending、审计和现场。没有新业务事实之前，可按已保存配置恢复原代码／原服务／原入口，但须确认迁移 010 和身份锁协议的兼容及旧角色恢复范围。已有新登录或消费事实时，先停止新准入并保留最新事实，优先修复当前权威库；不得恢复旧账本快照继续消费、清空未知费用或删除身份映射来伪装回退。

恢复旧服务也须逐项核对 owner、路径、PID／启动时间、端口和管理器，不能直接执行会再次 provision 的旧脚本。完成并验证服务器独立登录、备份恢复和新入口后，再单独安排移除 Mac 依赖与旧入口；本批不删除旧数据、数据卷或原预览。
